# Serve

Purpose: The tailnet HTTP/1.1 server of the `ont` command (`ont serve`), exposing reads, actions, functions, and MCP over HTTP with Tailscale LocalAPI peer authentication.

`ont serve` is the single tailnet listener exception to "No daemon" in the repository's `AGENTS.md` ("The engine").

## CLI and startup

- R1: `ont serve --bind ADDR:PORT [--tailscale-socket PATH] [--store PATH] [--now U64] [--client NAME]` starts the tailnet HTTP server. `--bind` is required and must parse as a `SocketAddr` (missing or unparsable refuses exit 2 `invalid_argument` with `field` `--bind`). `--tailscale-socket` defaults to `/run/tailscale/tailscaled.sock` and must be an absolute path without NUL (else exit 2 `invalid_argument` with `field` `--tailscale-socket`). `--client`, when given, must satisfy `valid_client` (`invalid_request` on `--client`). `ONT_FN_READ_ONLY=1` refuses `ont serve` with `read_only_call`; `--now` requires `--store` (`now_requires_store`) and refuses `now_at_default_store` on the default store (action.md R104); `check_uid` (real = effective = 0) applies as for every command.
- R2: Tailnet-only bind rule: before calling `TcpListener::bind`, `ont serve` verifies that `--bind`'s IP lies in Tailscale's IPv4 range `100.64.0.0/10` (`octets[0] == 100 && (octets[1] & 0xc0) == 0x40`) or IPv6 range `fd7a:115c:a1e0::/48` (`segments[0..3] == [0xfd7a, 0x115c, 0xa1e0]`). Any other address (`0.0.0.0`, `::`, `127.0.0.1`, `::1`, LAN, or public IP) refuses exit 2 `bind_not_tailnet` (`field` `--bind`) before any socket is bound; no CLI flag or environment variable weakens this check.
- R3: Before binding or accepting connections, `ont serve` verifies that the store exists and opens cleanly via `Store::open_schema_existing` (never creating or initializing a store file; missing, symlinked, upgrade-required, or corrupt stores fail as other commands do). `ont serve` keeps one process family and shuts down cleanly via the library `shutdown` flag (stopping accept and draining active in-flight connections) or on `SIGINT`/`SIGTERM`.

## Tailscale peer identity

- R4: For every accepted TCP connection, the server reads `peer_addr = stream.peer_addr()` from the kernel socket (never from `X-Forwarded-For`, `Host`, request headers, or JSON body) and resolves it through `PeerIdentityResolver`. The production `TailscaleWhois` resolver connects to `--tailscale-socket` over Unix domain socket (5 s read/write timeout), sends `GET /localapi/v0/whois?addr=<percent-encoded-peer-addr> HTTP/1.0\r\nHost: local-tailscaled.sock\r\n\r\n`, reads at most 65,536 bytes, decodes `Transfer-Encoding: chunked` within that 65,536-byte cap if the server responds chunked, and requires HTTP 200 and a JSON object containing `Node` and `UserProfile`.
- R5: Peer identity derivation from whois JSON: `host` is `Node.ComputedName` if non-empty, else the first label of `Node.Name` before `.`, and must be 1..=64 ASCII bytes of `[A-Za-z0-9._-]`. `principal` is `ts:<t>` where `t` is the lexicographically smallest non-empty string in `Node.Tags` when `Node.Tags` is a non-empty array of strings; otherwise `ts:<LoginName>` where `UserProfile.LoginName` is non-empty and not `"tagged-devices"`. The resulting `principal` must pass `principal_form` (action.md R113).
- R6: Any whois socket error, timeout, non-200 status, oversize or malformed response, or invalid host/principal rejects the request with HTTP `403 Forbidden` and JSON refusal `{"status":"refused","code":"peer_not_identified",...}` without opening the store.
- R7: Remote `action validate`, `action apply`, and `fn` propagate the authenticated peer `EngineIdentity` internally (without adding public identity fields to `Context` or changing public operation signatures) so actor logging (`principal`, `host`, neither in `claimed`), criteria evaluation, refusal logging, and `RoleResolver` checks against `roles.json` use the peer's `ts:` principal and node host, while local calls retain kernel identity (action.md R101).

## HTTP/1.1 wire contract and endpoints

- R8: Strict HTTP/1.1 framing and containment: incoming `Transfer-Encoding` headers refuse `400 Bad Request` (`unsupported_transfer_encoding`); header blocks exceeding 16,384 bytes refuse `431 Request Header Fields Too Large` (`headers_too_large`); malformed request lines or headers refuse `400 Bad Request` (`malformed_request`); connections enforce a 30 s read/write timeout; responses always carry `Connection: close` and `Content-Type: application/json`; concurrent in-flight connections are capped at 16 (overflow returns `503 Service Unavailable` with `code` `server_busy`); handler panics are caught with `catch_unwind` and the panic recorder and answered `500 Internal Server Error` with `{"status":"internal","code":"panic@<file>:<line>"}` without crashing the server.
- R9: Remote attribution headers and environment isolation: server process environment variables `ONT_ROLE` and `ONT_AGENT` are never inherited by remote requests. Case-insensitive optional headers `X-Ont-Client` (validated by `valid_client`, default `--client` or `"remote"`, literal `"cli"` mapped to `"remote"`), `X-Ont-Agent` (validated by `valid_actor_field`, fallback when the request body omits `agent`), and `X-Ont-Role` (validated by `valid_actor_field`, used for `/v1/fn`, `/mcp`, and fallback when `/v1/action/validate` or `/v1/action/apply` omits `role`, resolved against `roles.json` for the peer's `ts:` principal) supply claimed attribution; invalid header values refuse `400 Bad Request` (`invalid_request`). Request body fields `principal` and `host` remain refused as unknown fields.
- R10: Plain JSON endpoints accept `POST` with a body of at most `MAX_REQUEST` (65,536 bytes; larger returns `413 Payload Too Large` with `code` `request_too_large`; non-`POST` returns `405 Method Not Allowed` with `code` `method_not_allowed`): `/v1/describe`, `/v1/get`, `/v1/search`, `/v1/around`, `/v1/aggregate`, `/v1/log`, `/v1/render` (read-only view render only, no file writes), `/v1/fn`, `/v1/action/list`, `/v1/action/validate`, and `/v1/action/apply`.
- R11: Status codes on `/v1/*`: `200 OK` on exit 0, `400 Bad Request` on exit 2 refusal (exact `ont` refusal JSON body), and `500 Internal Server Error` on exit 1 internal failure (`{"status":"internal","code":"<code>@<file>:<line>"}`). Host-local admin operations (`index`, `backup`, `schema`, `render --write`) are not exposed; any unknown path returns `404 Not Found` (`{"status":"refused","code":"unknown_endpoint",...}`).
- R12: `GET /healthz` runs only after Tailscale peer authentication and returns `200 OK` with `{"status":"ok","service":"ont-serve","version":"<ONT_BUILD_REVISION>"}` without opening the store; non-`GET` returns `405 Method Not Allowed` (`method_not_allowed`).
- R13: `POST /mcp` accepts one JSON-RPC 2.0 message of at most `mcp::MAX_LINE` (1,048,576 bytes; larger returns `413 Payload Too Large` with JSON-RPC `-32600` `request_too_large`; non-`POST` returns `405 Method Not Allowed` `method_not_allowed`), handles `initialize`, `ping`, `tools/list`, `tools/call`, and notifications with the peer's authenticated `EngineIdentity` and remote attribution (never inheriting server `ONT_ROLE`/`ONT_AGENT`), and returns `200 OK` with JSON-RPC response or `202 Accepted` with empty body for notifications.
- R14: On remote `POST /mcp`, calling `ont_index` is refused with `operation_not_served` while `ont_action_apply` remains available (not reusing `mcp::Config.read_only`).
- R15: The library exposes `ont::serve::{Config, PeerIdentityResolver, TailscaleWhois, is_tailnet_ip, serve_listener}` so callers and integration tests can serve an already-bound `TcpListener` with an injected resolver or a temporary Unix domain socket speaking Tailscale LocalAPI `/localapi/v0/whois`, with zero network access.

## Not included

- The bind check validates Tailscale IP ranges (`100.64.0.0/10` and `fd7a:115c:a1e0::/48`) rather than querying OS interface ownership, while Tailscale LocalAPI whois authenticates every peer connection.
- TLS termination inside `ont serve` (transport encryption and peer authentication are provided by Tailscale WireGuard and LocalAPI whois).
- Streaming SSE or long-lived MCP sessions (each `POST /mcp` carries one JSON-RPC 2.0 message).
- Systemd unit installation, remote CLI transport, and host-local admin operations (`index`, `backup`, `schema`, `render --write`).
