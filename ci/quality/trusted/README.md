## Execution and proof

`controller.ts` executes only P code on the report host. It obtains actual provider objects, constructs full-history token-free source checkouts using fixed Git commands, checks canonical committed source-author metadata, actual commit/tree/source manifests and the ordered mechanical merge. A PR tests H and M separately. Protected main tests the actual merged main commit, with actual parents `[B,H]`; it does not manufacture a successful prospective skip.

`worker.ts` builds the pinned Node 22.23.3 linux/amd64 recipe with the exact Bun 1.4.3 archive/binary. It records the actual official-base metadata and actual local built image ID. There is no fabricated registry digest or registry publication prerequisite. Every new worker is inspected before start: UID1000, dropped capabilities, no-new-privileges, read-only root/P, bounded private tmpfs, resource limits, private PID/IPC and an exact mount/environment denominator. No Docker socket, native Home, App key/token or controller output path is mounted. The controller retains create/start intents, exact IDs, inspect/output hashes, exit/OOM/timeout and original failure hashes outside all worker mounts/process namespaces. An unknown create/start/build is not retried.

Preparation and audit are distinct credential-free network workers. Installation receives only committed package manifests, a present frozen lock and local archives, without candidate bunfig, npmrc, env, preload or source execution. `--ignore-scripts` is mandatory. P pins the tools; prepared source/dependency/tool volumes become read-only before all offline checks. A separate P-selected real Bun audit binds exact inputs, result bytes, configured npm bulk-advisory feed and bounded freshness. Its stdout hash is audit result evidence, not a claim to an independently archived upstream database version. Full quality requires this phase and the complete offline denominator; no `SKIP_AUDIT` or offline-only full pass exists.

P's static checker reads candidate bytes through P parsers, formatter, typed linter, architecture checker and maintained workflow/secret tools, without importing candidate implementation/configuration. The full old P package/quality/support denominator and candidate additions remain in canonical QA, using P controller/test/fixture/script projections. No selected test or generator is removed. The additional source and candidate-quality workloads must run and exit successfully, but their shared-process completion claims remain untrusted. Existing full required legacy CI contexts remain separate and unchanged.

Candidate changes cannot choose the case set; immutable P-prime promotion requires separate review.
