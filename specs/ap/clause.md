# Clauses: `ap clause index` and the function `clause`

Purpose: an implementer and a page reviewer ask what binds a change once, instead of reading files: each numbered sentence (`- R<n>:`) of a `specs/**/*.md` file at `origin/main` of the repositories this host works from is one record of the store's record source `clauses` (`specs/ont/index.md` R14 to R29 of the engine), with its repository, file, line, digest, text and the tests that cite it; `ont fn clause` answers one clause's sentence, its tests and the units that name it. The object, its source and the function are those of schema version 16 (`ontology/README.md`, "Version 16: clauses, the wave and the stored page digest").

## Requirements

- R1: `ap clause index [--directory <dir>] [--store <path>] [--prune] [--repository <owner/name>]...` takes its options with the rules `specs/ap/route.md` R1 to R3 give the same options, by the same code: in any order, `--repository` repeated, every other option at most once; an unknown option (`--instructions` among them), an option without its value or given twice, a first argument other than `index` and an argument that is not UTF-8 are `usage` (field `args`); an empty value is `invalid_input` with the option's name as the field; `--directory` is an absolute path; the default directory is `/var/lib/agent-platform/clause`, which `--store` may not name, and another directory needs `--store` (`invalid_input`, field `directory`); a repository's form, a name given twice and a repository part that begins with `education-` are `invalid_input` (field `repository`) before any fetch or other effect; the clone is the policy's (`repository_not_mapped`, `policy_invalid`). Every refusal of R1 prints `{"error":{"code","field","detail"}}` on standard error and exits 2. `ap clause` with no argument or with another first argument is `usage` (field `args`, exit 2); `ap clause --help` alone prints the usage.
- R2: For each repository named, in its clone, the command runs `git fetch --quiet origin main`, resolves `origin/main` to its commit once and reads every file at that commit with `git ls-tree` and `git cat-file` (no checkout is read or changed). A step of Git that fails leaves that repository's previous file as it was and lists it under `kept` with its reason (`fetch_failed`, `revision_unreadable`, `listing_failed`, `read_failed`, `log_failed`) and whether a previous file exists (`previous`), as `specs/ap/route.md` R4 says; the other repositories go on.
- R3: A clause: in each regular file (mode `100644` or `100755`) whose path begins with `specs/` and ends with `.md`, each line that begins with `- R`, digits and `:` (the rule of `ci/check-spec-trace.py`); its `rule` is `R<digits>`. A later line of the same rule in one file is not indexed and is counted in the answer's `duplicates`. The clause's lines run from that line to the line before the next blank line, the next such line or the next ATX heading, or to the file's end. `text` is their words (each run of white space one space), at most 4,000 bytes, cut at a character boundary; `digest` is the SHA-256 of those lines joined by line feeds; `line` counts from 1, at `\n`; `commit` is the last commit at that `origin/main` that changed the file (`git log -1 --format=%H <commit> -- <path>`, paths literal). A file over 1,000,000 bytes is not indexed. The key is `<owner>/<name>:<path>#R<n>`.
- R4: The tests. A citation is `spec: `, a path `specs/….md`, `#R` and digits (`CITE_RE` of `ci/check-spec-trace.py`) in a regular file of that repository at that commit whose path does not end in `.md` (a file over 1,000,000 bytes is not read). A clause's `tests` are its citations as `<path>:<line>`, ordered by path, then line, the first 100; `tests_total` counts all of them.
- R5: The files. One file `<owner>__<name>.clauses.jsonl` per repository, one JSON object a line: `type` `clause`, `observed_at` the run's time (seconds since 1970), `key` and the members `repository`, `path`, `rule`, `commit`, `line`, `digest`, `text`, `tests` and `tests_total`; written whole under a temporary name `.ap-clause.<pid>.<file>.tmp` in the directory and renamed. The directory is made with mode 0700 when it is absent (its parent must exist), set to mode 0700 when it has another mode, and refused `invalid_input` (field `directory`) when it is not a directory (a symbolic link included). Every `*.clauses.jsonl` regular file directly in it, a kept one included, has mode 0600 after the run. With `--prune`, a regular file directly in it whose name ends in `.clauses.jsonl` and is of no repository named is removed, so its records are retracted, and so is a temporary file of the command older than an hour; nothing else is ever removed there (no other file, no subdirectory, no symbolic link).
- R6: Then the command runs `ont index --source clauses` (with `--store` when given) and prints one JSON line on standard output: `status` (`ok`, or `index_failed` when the source did not hold), `directory`, `sources` (`clauses`: `records`, the lines its files in the directory hold after the run, and of the index answer `status`, `code`, `appended`, `renewed` and `retracted`, the count of retractions), `duplicates` (R3), `kept` (R2) and `removed` (R5). It exits 0 when the source held, 3 otherwise; a failure of its own (a file it cannot write, an engine that does not answer) prints `{"error":{"code","field","detail"}}` on standard error and exits 3, as `specs/ap/route.md` R13 says.
- R7: `ap` started with no argument and `ONT_FN_NAME=clause` in its environment (`specs/ont/fn.md` R8) is the function `clause`: it reads one JSON object, the parameters, from standard input, reads the store at `ONT_FN_STORE` (an absolute path) through the read calls of `crates/ap/src/store.rs` only, and prints one JSON value on standard output, exit 0. A parameter or input it refuses prints `{"error":{"code","field","detail"}}` on standard error and exits 2; a store it cannot read exits 3 (both are `function_failed` to the caller of `ont fn`).
- R8: The parameter is `key`, a string of 1 to 512 bytes; another member, or a `key` that is no such string, is refused `invalid_input` with the member as the field.
- R9: The answer is `{"clause": {"key", "repository", "path", "rule", "line", "commit", "digest", "text", "tests", "tests_total"}, "units": [{"unit", "state", "class", "wave"}], "units_total"}`. The clause is read by one `ont search` of `clause` with `eq` on `repository`, `path` and `rule`, the parts of the key; `"stale": true` is added only when that answer is not qualified. The units, of every state, are the objects of one `ont around` from that clause by `clause_units` with `limit` 12 (an answer of `ont` is at most 8 MiB), in its order; `wave` is null for a unit without one; `units_total` is its `matched`; its `qualified` is not read. A key of another form, or one with no current clause, answers `"clause": null`, no unit and `units_total` 0: the units that name such a key are for `clause_missing` of a later unit.
- R10: The door. The list of `specs/ap/door.md` R5 (one constant of `crates/ap/src/door.rs`) holds `route` and `clause`: `ap fn clause` from a stage of any role is served as `ap fn route` is.
- R11: The timer. `deploy/ap-clause.service` runs `/usr/local/bin/ap clause index --prune` with `--repository` `park-kyungchan/agent-platform`, `park-kyungchan/ontology-platform` and `park-kyungchan/agent-vps-operations`, with the lines of `deploy/ap-route.service` (`specs/ap/deliver.md` R52); `deploy/ap-clause.timer` starts it with `OnCalendar=*:5/10` and `Persistent=true`; `ap deliver` installs both files and enables the timer (`specs/ap/deliver.md` R48 to R50).
- R12: The command writes files only in its directory, the store only through `ont index`, and in a clone only what its fetch brings; the function writes nothing and applies no action.

## Interface

`ap clause index [--directory <dir>] [--store <path>] [--prune] [--repository <owner/name>]...`; `ont fn clause` with `{"parameters": {"key": "<owner>/<name>:<path>#R<n>"}}`. The schema's part (`ontology/work.schema.json`, version 16): the object type `clause`, the source `clauses` (kind `records`, glob `/var/lib/agent-platform/clause/*.clauses.jsonl`, `time_member` `observed_at`, `type_member` `type`, `complete_listing`, `fresh_for_s` 3600), the property `clauses` of `unit` with the link type `unit_clauses` (reverse `clause_units`), the function `clause` (`program` `/usr/local/bin/ap`, `timeout_ms` 10000, `answer_bytes` 65536) and `clause` in the grant's `read`. A unit names a clause by an entry `<path>#R<n>` of its `specs` (`specs/ap/unit.md` R43).

Codes of `ap clause index`: `usage`, `invalid_input`, `policy_invalid`, `repository_not_mapped` (exit 2); `io_error`, `process_failed`, `store_answer_unreadable`, `store_refused` (exit 3). Codes of the function: `invalid_input`, `input_too_large` (exit 2); `store_answer_unreadable`, `store_refused`, `process_failed` (exit 3).

## Not included

- The checks before a look and before ready (`read_first_missing`, `read_first_range`, `clause_missing`, `clause_unnamed`): a later unit. Here a named clause need not exist.
- The reading of a clause against its tests: a later unit.
- No `--instructions`, no Markdown outside `specs/`, no grant per function, no clause of another repository than a unit's own.
- No hook into `ap deliver`: the timer sees a merge within ten minutes; between, a changed clause carries its old text.
- A fetch that keeps failing keeps that repository's records as they were, which turn stale after an hour (`fresh_for_s`), and the function answers `stale`.
