# State: `ap state`

Purpose: a Lead reads what the files of a task directory and Git say of its unit calls and stages, and the form of the directory's `STATE.md`, instead of typing it into a file. `ap state` is read only: it writes nothing, makes no store call and runs no `ont`. A task directory has one form: a `STATE.md` of at most 30 lines, whose generated blocks `ont render` writes (`ontology/README.md`, "Version 21: documents and rule targets"), and no tree of run files; `ap state` still reads a `runs/` of the older form where it finds one.

## Requirements

- R1: `ap state <task directory> [--text]` takes the directory and at most one `--text`, in any order. A malformed argument list (no directory, another word or option, `--text` twice) and a path that does not resolve to a directory are refused with `{"error":{"code":"usage","field":"args","detail":null}}` on standard error and exit 2, with nothing on standard output.
- R2: It reads the files directly in `<directory>/runs/` (`*.unit.json`, `*.run.json`, `*.stream.jsonl`) with the file system, Git with `--no-optional-locks -c core.fsmonitor=false` (`rev-parse HEAD` and `status --porcelain`: no index lock, no refresh of the index, no hook named by the repository's configuration), `systemctl is-active` and `ps` through the host's `System`, and, for the form (R13), `<directory>/STATE.md` and whether `<directory>/runs` is a directory. It writes nothing (no file, no store call, no network, no `gh`), runs no program but `git`, `systemctl` and `ps`, reads no session record and no prompt or answer text, and changes no record's member.
- R3: A record that does not parse as one JSON object is listed in `unreadable` and the rest is printed, exit 0.
- R4: The answer is one JSON object on standard output, ended by a line feed, whose members are `at`, `task`, `units`, `stages`, `streams_without_record`, `limits`, `unreadable` and `form`. `at` is the time of the read (UTC, RFC 3339). `task` holds `dir` (the resolved directory), `head` (`git rev-parse HEAD` there, null when Git says nothing) and `uncommitted` (the number of lines `git status --porcelain` prints; null when that call fails, as without Git).
- R5: `units` holds the calls of `ap unit`, the records `runs/*.unit.json`, in chains: the records with the same `repository` and the same non-null `pull_request` are one chain, a call whose `pull_request` is null is a chain of its own. A chain has `item` (the `item.key` of its first call that has one, else null), `repository`, `pull_request` and `calls` in order of `start`, each with `record` (the path relative to the directory), `state`, `stopped_at`, `cause`, `head`, `merge_commit`, `start`, `end` (null where the record lacks the member) and `stale`. Chains are newest first by their last call's `start`.
- R6: `stages` holds every record `runs/*.run.json` whose `end` is null, and the newest 20 by `start` of those that belong to no unit call, newest first. A stage record belongs to a call when its path begins with the call's record path less `.unit.json`, followed by `.` (`runs/U-1.unit.json` owns `runs/U-1.implementer.md.run.json`, not `runs/U-1-2.fixer.md.run.json`). Each has `record`, `role`, `runtime`, `model`, `account`, `state`, `start`, `end`, `stale` and, where the record has it, `served_by`.
- R7: `stale` of a stage record whose `end` is null is read from `systemctl is-active` of its systemd unit (the record's `unit`): the answer is the word on standard output and the exit is not read. `active`, `activating`, `deactivating`, `reloading` or `refreshing` gives false; any other word, including `inactive` of a unit that does not exist (exit 4), gives true; no word (the call failed, timed out or printed nothing) gives null. A record whose `start` is less than 10 seconds before `at` prints null where true would be printed, because `ap run` writes the record before it starts the unit. `stale` of a unit call whose `state` is `running` is false when one of its stage records (the ownership of R6) is live (its `stale` is false), else true when no process of `ap unit` lives on the host (`ps`: a process whose program is named `ap` and whose first argument is `unit`), else null (some `ap unit` lives and nothing ties it to this record); a failed `ps` call, a non-zero exit or empty output gives null for a call that no live stage decides. `stale` is null for every record that does not say it runs. `stale: true` speaks only for this host's service manager and process table: a stage or call that runs under another host's manager is stale here.
- R8: `streams_without_record` holds the files `runs/*.stream.jsonl` that have no `.run.json` of the same stem (stages started by hand), each with `path` and `modified` (the modification time, UTC).
- R9: `limits` holds, per account named by a stage record (every readable `*.run.json`), the newest record by `end`, else `start`, whose `limit` is present and not null: `account`, `record` and that `limit`; a missing `limit` counts as null; an account with none is not listed.
- R10: `unreadable` holds the paths of the `*.unit.json` and `*.run.json` files that do not parse as one JSON object.
- R11: `--text` prints the same as plain lines after the form line (R14): first every stage record that runs (`end` null) and every unit call that is `running`, each with the word `stale` when it is, then the newest ten chains (item, pull request, last state, the merge commit or the head in its first 12 characters, end), then one line per account with a limit. A line break inside a value is printed as a space.
- R12: A directory without `runs/` (no entry of that name, or one that is not a directory) is answered, exit 0, with `units`, `stages`, `streams_without_record`, `limits` and `unreadable` empty, `task` read from Git as for any directory, and no call of `systemctl` or `ps`.
- R13: `form` is `{"state_md": null | {"lines": <n>, "limit": 30, "blocks": <k>}, "run_tree": <bool>}`. `state_md` is null when `<directory>/STATE.md` is absent or is not a regular file, read without following a symbolic link; otherwise `lines` counts its lines (split at `\n`, a last line without `\n` counted, an empty file 0), `limit` is 30 and `blocks` counts its lines that begin with `<!-- ont:render ` (the opening line of a generated block). `run_tree` is true when `<directory>/runs` is a directory.
- R14: `--text` prints first the line `form: STATE.md <n> of 30 lines, <k> rendered blocks, runs/ absent`, with `present` for `absent` when `run_tree` is true and ` over` appended to the line when `n` is more than 30; when `state_md` is null the line is `form: STATE.md absent, runs/ absent` or `form: STATE.md absent, runs/ present`. Where the base's lines (R11) are more than 59, the lines after the form line are the first 58 of them and the line `... <m> more lines: ap state without --text prints them all`, `<m>` the number of the base's lines not printed, so that at most 60 lines are printed in all. Where there is no line of R11, the output is the form line and its line feed alone.

## Interface

`ap state <task directory> [--text]`: one JSON object on standard output (R4), or the lines of R11 and R14 with `--text`; `usage` (field `args`) with exit 2 (R1). The task directory's own form is `STATE.md` (`ontology/README.md`, "Version 21: documents and rule targets"; the skill `lead`, section 4).

## Not included

- No check that a generated block of `STATE.md` is current: `ont render --check STATE.md` does that. No read of fenced code, of `HANDOVER.md` or of `BOTTLENECKS.md`.
- It does not print the installed revisions (`deploy/README.md`, "Read the state"), the store's holds, items and rows, or the host's disk and CPU.
- It does not remove or write a `runs/` tree: `ap unit <page>` still writes `<page directory>/runs/`, and `ap state` reads what it finds.
