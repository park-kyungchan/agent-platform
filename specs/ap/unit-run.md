# One unit driven from its object: `ap unit run`

Purpose: one call takes a unit of the store (schema version 11) from `ready`, `stopped` or a cut run to `accepted` or `stopped`: it makes the worktree, runs the implementer, checks the head (the write set, the acceptance checks, the required check), has a verifier judge exactly that head, and runs up to two repairs inside, each state and review written to the store, so that the Lead calls once per unit instead of once per round.

## Requirements

- R1: The form is `ap unit run <key> [--store <absolute path>]` (arguments only, no standard input); any other argument is `usage` (field `args`), and the present forms of `ap unit` answer as before. With `ONT_ROLE=lead` in the environment the call is refused `role_in_environment` (field `ONT_ROLE`) before any call to the store. The run's own actions carry the client `ap`, the agent `ap-unit` and the session `u-<key>`, and no role; every apply has the request id `ur-<16 hexadecimal characters drawn once per call>-<counter>`, the counter from 1 in the call, reused only by the retry of `store.rs`.
- R2: Before any directory is made or anything applied, each refused with exit 2: the key has the form of a new key of `ap unit add` (1 to 59 bytes, lower-case ASCII letters, digits and `-`, beginning with a letter), else `invalid_input` (field `unit`); the unit is read with one `ont get` (`unknown_unit`); it has a repository (`no_repository`); its `branch`, or `unit/<key>` when it names none, has the form of `specs/ap/unit.md` R10 and is taken by `git check-ref-format --branch` (`invalid_branch`); the policy file has a `repositories` entry for the repository (`repository_not_mapped`, `policy_invalid` as `ap unit ready`), a `reviews.task` (`invalid_input`, field `task`); each tier's runtime is `claude` (`tier_not_supported`, field `implementer` or `verifier`) and has an account (R4).
- R3: The policy file's member `units` is `{"directory", "timeouts": {"implementer", "verifier", "fixer"}}`, each optional (defaults `/var/lib/agent-platform/units`, 10,800, 7,200 and 7,200 seconds; a timeout is 1 to 86,400); a member of another name or form is `policy_invalid` (field `policy`, `detail` a sentence that begins with the member); the directory fits the schema's `file_path`. It is made with mode 0700 and resolved once (links and `..`); `<directory>/<key>` (mode 0700) holds the lock `lock`, the worktree `wt`, every prompt (`<n>.<stage>.prompt.md`) and every author stage's files (`<n>.implementer.md`, `<n>.fixer.md` with `ap run`'s suffixes), `<n>` counting the stages of the unit from 1. A verifier's report is `<reviews.directory>/<review key>.md` with its run record beside it.
- R4: A stage's accounts are the list of the first key present among `<runtime>/<role>`, `<runtime>/<model>` and `<runtime>` of the policy file's `accounts` (`specs/ap/policy.md` R6): the first path is `account`, the rest `next_accounts`; the role is `implementer` for the implementer's tier (its fixer and settling stages use the same accounts) and `reviewer` for the verifier's. No key: `account_not_mapped` (field `implementer` or `verifier`); a list that is not 1 to 5 strings: `policy_invalid`. Every stage on Claude Code has `permission_mode` `auto`.
- R5: The call first takes an advisory lock (`flock`, without waiting) on the open file `<directory>/<key>/lock`, which the kernel releases when the call ends or dies; another call that holds it refuses `unit_run_active` (exit 2). `<directory>/<key>` must be a directory and not a link (`worktree_failed`).
- R6: Then by the state read: `ready` applies `start_unit`, `stopped` `resume_unit`, each with the unit's `intent` in the lane `objective`; a refusal of the store is passed on with its code (exit 2) and nothing else happens. `running` (an earlier run was cut) applies nothing: the view `holds_on_work` is read and an active hold that names the unit or its intent refuses `held`. `accepted` answers R25 and applies nothing. Any other state is `unit_not_runnable` (`detail` the state).
- R7: The leftovers, before the loop: for every author record under `<directory>/<key>/` and the record of every `running` review of kind `packet` of the unit, a record whose `state` is `running` has its unit of the service manager stopped (`systemctl stop`) and read as ended (`systemctl is-active`) only when its name is `ap-run-<36 of 0-9a-f->.scope`; a unit of another name, or one not read as ended, refuses the call `run_still_active` (`detail` the name). A record's `run` object still `running` whose `record` is that record's path is closed with the record's state (`killed` for `running`) and the stage's own request id. A `running` review is closed `abandoned` with the record's session, else with the session `u-<key>:recovery` (also when the store refuses the record's session as a writer).
- R8: Each pass fetches `origin main` in the clone (`fetch_failed`) and takes ONE base commit, `refs/remotes/origin/main` resolved; Git names the unit's branch `refs/heads/<branch>` where it takes a revision. Before the worktree is used, `<directory>/<key>` and `<directory>/<key>/wt` are directories and not links, and `git worktree list --porcelain` of the clone has an entry whose path is exactly `<directory>/<key>/wt`, else `worktree_failed`.
- R9: The read of the hosting service: while the unit holds no `pull_request`, the open pull requests of the branch against `main` whose head repository is the repository itself (`isCrossRepository` false and the same owner and name); more than one is `pull_request_ambiguous`; one found while the unit has no author record is `branch_in_use`. A unit that holds one reads that number only; a pull request that is not open is `pull_request_not_open`; an unreadable answer is `github_unreadable`.
- R10: No worktree: `git worktree add -b <branch> <wt> <base>`; a branch that exists already must be the unit's own (a worktree entry of the clone at `wt` on `refs/heads/<branch>`, or a pull request the unit holds), else `branch_in_use`, and is checked out as it is (`git worktree add <wt> <branch>`); a failure is `worktree_failed`.
- R11: No pull request: the implementer stage, with the text of `ap unit page <key> --for implementer`, the unit's `implementer` tier, `unit`, `git_author: true` and `store`. When an implementer record names a session, the newest such session is resumed and the frame `continue.md` follows the page; else a worktree that is not clean, is not on the branch or holds commits beyond the base is `worktree_dirty` (`detail` the counts) and nothing starts. A stage `ap run` refuses stops `stage_refused` (`detail` the code and the field). After the stage the hosting service is waited for (R20); still no pull request is `no_pull_request` with the stage's end state and the first bytes of its answer.
- R12: A clean worktree on the branch whose HEAD is an ancestor of the pull request's head but not that head is moved there (`git fetch origin refs/heads/<branch>` in the clone, `git merge --ff-only <head>` in the worktree). A worktree in any other state is settled by its author: when the newest verdict is `repair` and the newest author record is a fixer's that did not end `ok`, the repair step runs again (R21); else the newest author record's session is resumed with `continue.md`, under the role of that record, and the hosting service is waited for. One settling stage per call; a worktree still in such a state after it, or one no session can settle, is `worktree_dirty`.
- R13: When the unit's `amended_at` is later than the start of its newest author record, it has a pull request, the worktree is clean at the pull request's head and no author record that started after `amended_at` ended `ok`, that author gets ONE turn in a call in the form of R12's settling stage. A unit with a pull request and no author record gets none.
- R14: A pull request's head that is not the unit's `head` is recorded: `record_head` with the head, the number, `rounds` (R18) and `writers`, the union of the unit's `writers` and the session of every `attempts` entry of every author record.
- R15: A head that does not contain the base commit is `behind_main`.
- R16: The deterministic checks: the worktree clean at the head (`worktree_dirty`); every path changed between the base and the head inside the write set (`path_outside_write_set`, up to ten paths); each acceptance check, run by the runner of `ap unit ready` in the worktree with `AP_BASE` the merge base and `AP_HEAD` the head, ends 0 (`acceptance_not_runnable` without a status, `acceptance_timeout` for 124 or 137, else `acceptance_failed`, each with the check's index); the worktree clean after them.
- R17: The required check: the gate of `ap gate` on the number and the head, without the automatic reviewer; an end other than `passed` stops with the end as the cause, and an unresolved review thread stops `unresolved_threads`.
- R18: The verdict of a head is that of the newest review of kind `packet` of the unit that names the head, is `closed` with `accept` or `repair`, and started later than `amended_at`. `rounds` is the number of such reviews of any head, `repairs` the number with `repair`. No verdict: a verifier round (R19). `repair`: the repair step (R21). `accept`: `accept_unit` with the head, and the call answers `accepted`.
- R19: A verifier round: the stage admitted by `ap run`'s code, ONE `ont action validate` naming the review's key, `start_unit_review` (kind `packet`, the head, `round` = `rounds` + 1, the unit, the repository, the pull request, the task `reviews.task`), the stage (role `reviewer`, `ont_role` `verifier`, the verifier's tier, the worktree as its directory, the text of `ap unit page <key> --for verifier`), `close_unit_review`. It resumes the session of the newest verdict, with the frame `second-look.md` and `## The round`, only when this call's own fixer moved the head since that verdict, that session is not a writer and the newest review started after `amended_at` is not `abandoned`; else it is a new session. A report whose first line is not `Verdict: accept` or `Verdict: repair`, whose second line does not name exactly the head, or whose bytes are not those the record names closes the review `abandoned` and stops `verifier_failed`.
- R20: After a verifier the worktree must be clean and at the head, and the pull request's head on the hosting service the head; else `verifier_wrote`: the review closes `abandoned`, then `record_head` of the pull request's present head adds the verifier's session to `writers`, then the unit stops. After an author stage the local head is waited for on the hosting service (up to 120 seconds, `head_not_seen`).
- R21: The repair step: the third `repair` (`repairs` is 3) stops `repair_limit`. Else the fixer resumes the newest author record's session, with the page for the implementer, the frame `fixer.md` and `## The round` (the head judged and the path of the verifier's report), the implementer's tier and accounts and the `fixer` timeout. A fixer that left the head unchanged is `repair_refused` (`detail` its end state and the first bytes of its answer).
- R22: Every stop is `stop_unit` with the cause and a detail of at most 1,000 bytes cut at a character boundary; the call then answers `stopped` (exit 3). A refusal or a failure of the store after the first apply ends the call at once: `store_refused` (`detail` the store's refusal) or the failure's code, exit 3, no further step.
- R23: The run applies no `approve_unit` and no `merge_unit`, pushes nothing, removes nothing and merges nothing but the fast-forward of R12; it stops only a unit of the service manager of R7's form that a record of this unit names.
- R24: The frames `fixer.md`, `second-look.md` and `continue.md` are compiled in byte for byte from `crates/ap/src/unit/frames/`; the run appends a frame and `## The round` after the text `ap unit page` gives, which does not change.
- R25: The answer, one JSON object on standard output: `unit`, `state` (`accepted` or `stopped`), `head`, `pull_request`, `rounds`, `repairs`, `reviews` (`[{key, round, head, verdict}]` of every review of kind `packet` of the unit, by `started_at`), and `waits_for` (`approve` for the classes `contract` and `effect`, `merge` for `plain`) or `stop_cause` and `stop_detail`. Exit 0 for `accepted`, 3 for `stopped`; a refusal is one line `{"error":{"code","field","detail","unit"}}` on standard error, exit 2 before the run applied anything, else 3.

## Interface

`ap unit run <key> [--store <path>]`. The policy file's member `units`: `{"directory", "timeouts": {"implementer", "verifier", "fixer"}}`, each optional.

Codes of `ap` itself: `usage`, `invalid_input`, `role_in_environment`, `unknown_unit`, `no_repository`, `invalid_branch`, `repository_not_mapped`, `policy_invalid`, `tier_not_supported`, `account_not_mapped`, `unit_run_active`, `held`, `unit_not_runnable`, `run_still_active`, `store_refused`, `store_answer_unreadable`, `store_answer_unqualified`, `process_failed`. The store's refusals of `start_unit` and `resume_unit` pass on with their codes (`held`, `dependency_not_merged`, `intent_not_confirmed`, `unit_not_ready`, `unit_not_stopped` and the others).

Stop causes: `fetch_failed`, `worktree_failed`, `github_unreadable`, `pull_request_ambiguous`, `branch_in_use`, `pull_request_not_open`, `worktree_dirty`, `stage_refused`, `no_pull_request`, `head_not_seen`, `behind_main`, `path_outside_write_set`, `acceptance_failed`, `acceptance_timeout`, `acceptance_not_runnable`, the ends of the gate (`check_failed`, `check_timeout`, `head_differs`, `head_moved`, `merged`, `closed`, `ready_failed`), `unresolved_threads`, `verifier_failed`, `verifier_wrote`, `repair_limit`, `repair_refused`, `git_failed`, `io_error`.

## What the Lead does after a stop

A stop that a later call would only repeat (`acceptance_failed`, `path_outside_write_set`, a gate end that did not pass, `unresolved_threads`, `behind_main`, `repair_limit`, `repair_refused`, `no_pull_request`) has two ways out: amend the page (`ap unit amend`), have it reviewed where its class asks (`ap unit review`), make the unit ready (`ap unit ready`) and run it again, which gives the author ONE turn on the amended page (R13) and counts `rounds` and `repairs` anew from the amendment; or drop it (`ap unit drop`). `behind_main` waits for the unit that brings the update of a branch behind `main`. A stop on a cause outside the unit (`fetch_failed`, `github_unreadable`, `head_not_seen`, `stage_refused`, `worktree_failed`) is run again once its cause is gone: `resume_unit` takes the unit back on the same page.

## Trust

The stages' sessions are claims of `ap run`'s records; `writers` holds every session that an author record names, so the store refuses each of them as the closer of a review of the unit. A verifier that writes or pushes becomes a writer before the unit stops. The run trusts no path or name of a record or of the store before it was checked: a stage's unit by its form, a run object by its record path, a review's report by its key.

## Not included

- Everything after `accepted`: the update of a branch behind `main`, the approval, the merge, the cleanup of a merged or dropped unit's worktree.
- A unit without a repository, a tier of another runtime, a verifier beside the required check, a carried verdict, protected paths, the dispatch pass.
- Two leftovers the run cannot find: a check's own unit, which ends by its bound of 320 seconds, and a `run` object left `running` by a call that died between `start_run` and the record's first write.
