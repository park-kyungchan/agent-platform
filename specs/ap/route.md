# Routes: `ap route index` and the function `route`

Purpose: a reader asks where a fact lives once, instead of reading files. `ap route index` writes one record per heading of the Markdown this host works from (the files at `origin/main` of the repositories it is given and the installed shared instructions) and one per component of each repository's `map.json`, as lines of the store's record sources `sections` and `components` (`specs/ont/index.md` R14 to R29 of the engine); `ont fn route` answers from their current objects with the best matching sections and components: path, lines, heading, commit and the words that matched. The objects and the function are those of schema version 14 (`ontology/README.md`, "Version 14: routes").

## Requirements

- R1: `ap route index [--directory <dir>] [--store <path>] [--prune] [--repository <owner/name>]... [--instructions <dir>]` takes its options in any order; `--repository` may be repeated, every other option is given at most once. An unknown option, an option without its value, an option given twice, a first argument other than `index`, and an argument that is not UTF-8 are refused `usage` (field `args`); an empty value is `invalid_input` with the option's name as the field. `--directory` and `--instructions` must be absolute paths (`invalid_input`, fields `directory` and `instructions`).
- R2: `--directory` (default `/var/lib/agent-platform/route`, the directory the host store's sources read) is where the command writes. `--store` with the default directory (absent, or given as that path with or without a final `/`), and another directory without `--store`, are refused `invalid_input` with the field `directory`, so a scratch store never feeds the host's sources and the host store never indexes a scratch directory.
- R3: A `--repository` is `<owner>/<name>` (an owner of ASCII letters, digits and `-`; a name of those and `.` and `_`, not `.` or `..`); a name whose repository part begins with `education-` or `academy-` is refused `invalid_input` (field `repository`) before any fetch or other effect, as are a name of another form and a name given twice. Each repository's clone is the policy's `repositories.<owner/name>.clone` (`specs/ap/unit.md` R22); a repository the policy does not map is refused `repository_not_mapped`, a policy that cannot be read `policy_invalid`, both before any effect. Every refusal of R1 to R3 prints `{"error":{"code","field","detail"}}` on standard error and exits 2.
- R4: For each repository named, in its clone, the command runs `git fetch --quiet origin main`, resolves `origin/main` to its commit once and reads every file at that commit with `git ls-tree` and `git cat-file` (no checkout is read or changed); a step of Git that fails (a fetch that fails, also on Git's ref lock while another command fetches the same clone, a commit that cannot be resolved, a listing, a read or a log that fails) leaves that repository's previous files as they were and lists it under `kept` with its reason (`fetch_failed`, `revision_unreadable`, `listing_failed`, `read_failed`, `log_failed`, `map_unreadable`) and whether a previous file exists (`previous`); the other repositories go on.
- R5: Of a repository, every regular file (mode `100644` or `100755`) whose path ends in `.md` is indexed; a symbolic link and a submodule are not. A section's `repository` is `<owner/name>`, its `path` the path in the repository, its `commit` the last commit at that `origin/main` that changed its file (`git log -1 --format=%H <commit> -- <path>`, paths literal), so a merge that does not touch a file changes none of its sections, and its `digest` the SHA-256 of the file's bytes.
- R6: With `--instructions <dir>`, every regular file under `<dir>` whose name ends in `.md` is read on disk, not through a symbolic link and not under a name that begins with `.`; its sections' `path` is absolute (`<dir>/<relative path>`), and they have no `repository` and no `commit` member. A directory that cannot be read keeps the previous file of the instructions (`kept`, reason `instructions_unreadable`, `repository` null).
- R7: The components of a repository are those of `map.json` at the root of that `origin/main`: one record each with `repository`, `name`, `purpose` (at most 4,000 bytes), `paths`, `entry`, `spec`, `tests` (an absent member is the empty string or list) and `commit`, the last commit that changed `map.json`. An absent `map.json` is zero components, not a failure; one that is not JSON, has no array `components`, or has a component without a name, a name twice or a member of another type keeps the repository's files (R4, reason `map_unreadable`).
- R8: The files are `<owner>__<name>.sections.jsonl` and `<owner>__<name>.components.jsonl` per repository and `instructions.sections.jsonl`, one JSON object a line, with the member `type` (`section` or `component`) and `observed_at` the run's time (seconds since 1970). Each file is written whole under a temporary name `.ap-route.<pid>.<file>.tmp` in the directory and renamed, mode 0600; a directory that is absent is made with mode 0700 (its parent must exist), one of another mode is set to 0700, one that is not a directory (a symbolic link included) is refused `invalid_input` (field `directory`). Every regular file of the two sources directly in the directory, a kept one included, has mode 0600 after the run. With `--prune`, after the files are written, a regular file directly in the directory whose name ends in `.sections.jsonl` or `.components.jsonl` and is not of a repository named, nor `instructions.sections.jsonl` when `--instructions` was given, is removed, so its records are retracted; so is a temporary file of that form older than an hour. Without `--prune` nothing is removed; nothing else is ever removed there (no other file, no subdirectory, no symbolic link), whatever directory `--directory` names.
- R9: A file's sections: one per ATX heading (up to three spaces, one to six `#`, then the end of the line, a space or a tab; a closing sequence of `#` after a space removed) outside fenced code (a fence opens with up to three spaces and three or more backticks or tildes, a backtick fence whose info string holds no backtick, and closes with at least as many of the same character and nothing else on the line; an unclosed fence runs to the end of the file). A section's lines are its heading line to the line before the next heading of the same or a higher level (fewer `#`), or to the file's last line; its `heading` is the heading path, the texts of its parent headings and its own joined by ` > `.
- R10: The text above a file's first heading is one more section, and a whole file without a heading is one section, each with the file's name (its last path component) as `heading`, from line 1; when those lines are all blank (an empty file included) there is no such section.
- R11: Bounds: a section's `text` is the words of its lines, the heading line included (each run of white space and control characters one space), at most 4,000 bytes, cut at a character boundary; a heading path is at most 1,000 bytes, cut the same way; a file larger than 1,000,000 bytes or with a path longer than 1,024 bytes is not indexed. Lines are counted from 1, at `\n`; bytes that are not UTF-8 are read as U+FFFD.
- R12: A section's key is the hex SHA-256 of the JSON array `[<owner/name> or "instructions", <path>, <heading path>, <ordinal>]`, the ordinal counting from 1 the sections of that file with an equal heading path, so the key stays when lines are added or removed above the section, and is 64 bytes, under the engine's key bound. A component's key is the hex SHA-256 of `[<owner/name>, "map.json", <name>, 1]`.
- R13: Then the command runs `ont index --source sections --source components` (with `--store` when given) and prints one JSON line on standard output: `status` (`ok`, or `index_failed` when a source did not hold), `directory`, `sources` (per source `records`, the lines its files in the directory hold after the run, and of the index answer `status`, `code`, `appended`, `renewed` and `retracted`, the count of retractions), `kept` (R4, R6) and `removed` (R8). It exits 0 when both sources held, 3 otherwise; a failure of its own (a file it cannot write, an engine that does not answer) prints `{"error":{"code","field","detail"}}` on standard error and exits 3.
- R14: `ap route` with no argument or with a first argument other than `index` (and `--help` alone, which prints the usage) is refused `usage` (field `args`), exit 2.
- R15: `ap` started with no argument and `ONT_FN_NAME=route` in its environment (`specs/ont/fn.md` R8) is the function `route`: it reads one JSON object, the parameters, from standard input, reads the store at `ONT_FN_STORE` (an absolute path) and prints one JSON value on standard output, exit 0. A parameter or input it refuses prints `{"error":{"code","field","detail"}}` on standard error and exits 2, a store it cannot read exits 3 (both are `function_failed` to the caller of `ont fn`). Without `ONT_FN_NAME`, or with another name, `ap` with no argument is refused `usage` as at the base (`specs/ap/verbs.md` R4).
- R16: The parameters are `words` (a string, required) and `limit` (a whole number from 1 to 20, default 8; `null` is the default); a `limit` out of range or of another type, `words` that is not a string and any other member are refused `invalid_input` with the member as the field.
- R17: The candidates are the current objects of `section` and `component` of the store, every page of `ont search` read: a retracted object is never answered. When a page is not qualified (a head past its freshness because the timer stopped), the function still answers and adds `"stale": true`.
- R18: The answer is `{"answers": [...]}` with at most `limit` answers, best first, each `{"kind", "repository", "path", "first_line", "last_line", "heading", "commit", "matched", "score"}`: for a section its members (`repository` and `commit` null for the instructions), for a component `path` `map.json`, `first_line` and `last_line` null and `heading` its name; `matched` the words of `words` it matched, in their order; `score` rounded to three decimals. A candidate that matches no word is not answered. While the answer is longer than 60,000 bytes and holds more than one answer, the last is dropped, so it stays under the function's `answer_bytes`.
- R19: The words of a text: lower case, split at every character that is not a letter, a digit or one of `-`, `_`, `.`, `/` and `:`, those five trimmed from both ends of a word; a word of one character and a common English word are dropped. A word is compared in its stem: a word of ASCII letters only loses one ending `ing`, `ed`, `es` or `s` when at least three letters remain; any other word is compared as it is.
- R20: The match ranks the words of `words` against the `heading`, `path` and `text` of a section and the `name` and `purpose` of a component: each word that a candidate holds adds the weight of the highest field it is in (heading or name 3, path 2, text or purpose 1) times ln(1 + N / n), N the candidates and n those that hold the word in any field. Ties are ordered by path, then first line, then repository.
- R21: An answer is dropped when a section ranked higher has the same non-empty `text` (when that higher one is a section of a repository under `content/` and the dropped one is of the instructions, the instructions' copy takes its place), or when it is a section whose lines lie within those of a section ranked higher of the same file.
- R22: `deploy/ap-route.service` runs `/usr/local/bin/ap route index --prune` with `--repository` `park-kyungchan/lifecycle-platform` and `--instructions /root/.agents` (the engine is `engine/` of `park-kyungchan/lifecycle-platform`: its Markdown and the entries `engine-*` of the root `map.json` are indexed with that repository), and `deploy/ap-route.timer` starts it with `OnCalendar=*:0/10`; `ap deliver` installs both files (`specs/ap/deliver.md` R48 to R50), and `deploy/README.md`, "Routes", describes them.

## Interface

`ap route index [--directory <dir>] [--store <path>] [--prune] [--repository <owner/name>]... [--instructions <dir>]`; `ont fn route` with `{"parameters": {"words": <string>, "limit"?: <1 to 20>}}`. The schema's part (`ontology/work.schema.json`, version 14): the object types `section` and `component`, the sources `sections` and `components` (kind `records`, globs `/var/lib/agent-platform/route/*.sections.jsonl` and `*.components.jsonl`, `time_member` `observed_at`, `type_member` `type`, `complete_listing`, `fresh_for_s` 3600), the function `route` (`program` `/usr/local/bin/ap`, `timeout_ms` 2000, `answer_bytes` 65536) and the two types in the grant's `read`.

Codes of `ap route index`: `usage`, `invalid_input`, `policy_invalid`, `repository_not_mapped` (exit 2); `io_error`, `process_failed`, `store_answer_unreadable`, `store_refused` (exit 3). The evaluation that reads the answers is `evals/route/run` (`evals/README.md`, "The route suite").

## Not included

- No hook into `ap deliver`: the timer sees a delivery within ten minutes; between, the sections of a changed file carry the old commit and lines.
- Task directories are not indexed; neither are the repositories of the Academy (`education-*`, `academy-*`), nor a file of a repository outside `*.md` and `map.json`.
- No reader is told to use `route` yet.
- The ranking does not understand the words: a fact whose words the question does not share is not found, and a long question matches long sections.
- A fetch that keeps failing keeps that repository's records as they were, which turn stale after an hour (`fresh_for_s`), and the function answers `stale`.
