# Resources: `ap resource` and the functions `capacity` and `gate`

Purpose: a Lead, and later the dispatch pass, asks once what can start now and where, and whether the slots of the dispatch pass may grow, instead of reading a sampler's file, the checks log and the runs by hand. `ap resource` runs every five minutes: it records for this host (`local`) and for each host of the policy's `hosts` whether it answers, its CPUs, load and free memory, as an observation of the store's `host` object and as one line of a samples file indexed as `host_sample`; it indexes every line `ap check` wrote as a `check` object; it records the allowance the newest run of each account reports. `ont fn capacity` and `ont fn gate` answer from those objects. The objects and the functions are those of schema version 17 (`ontology/README.md`, "Version 17: hosts, accounts, samples and checks").

## Requirements

- R1: `ap resource [--directory <dir>] [--store <path>]` takes each option at most once, with a value that is an absolute path (else `invalid_input`, the option's name as the field). The default directory is `/var/lib/agent-platform/resource`, the one the host store's sources read; `--store` with the default directory (absent, or given as that path with or without a final `/`), and another directory without `--store`, are `invalid_input` (field `directory`), as `specs/ap/route.md` R2. `--help` alone prints the usage; any other argument list is `usage` (field `args`). The policy file is that of `specs/ap/policy.md` R1; without one the pass covers `local` alone and no account. A file that is unreadable, not JSON or not one JSON object, a `hosts` that the reader of `specs/ap/check.md` R16 refuses, a `work` that the reader of `specs/ap/work.md` R3 refuses, or an `accounts` that is not an object whose every value is an array of absolute paths is `policy_invalid` (field `policy`). These refusals print `{"error":{"code","field","detail"}}` on standard error and exit 2 before any effect.
- R2: The directory is made with mode 0700 when it is absent (its parent must exist) and set to 0700 when it has another mode; a path that is not a directory (a symbolic link included) is `invalid_input` (field `directory`), exit 2. Every file the pass writes there has mode 0600. The pass holds an exclusive advisory lock (`flock`) on `<dir>/resource.lock` (made when absent, never through a link), taken without waiting: a lock another pass holds answers `{"skipped":"pass_running"}`, exit 0, and the pass does nothing else.
- R3: This host, `local`. `cpus` is the count of the lines of `/proc/stat` that begin with `cpu` and a digit; `load_x100` the first number of `/proc/loadavg` times 100, rounded; `available_mb` the `MemAvailable` of `/proc/meminfo` in MB (kB divided by 1024, rounded down); each file is read through the port `System`. A file that cannot be read or parsed is `reading_failed` (field the path), exit 3, and the pass writes no line and applies no action. One search of `unit` by `state` in `ready` and `running` gives `units_running` (the units `running`), `units_ready` (the units `ready`) and `cpu_waits` (the `ready` units whose `waits_on` is `cpu outside` or begins with `cpu over `); `slots` is `work.slots` of the policy, 3 without one, read from the policy's JSON once the reader of work R3 admitted it. `local` answers (`answers` true) and is `free` when `units_running` is below `slots`. When that search fails, `units` is named in `failed`, the line and the observation of `local` hold the three readings and no count, and `free` is false.
- R4: A host of the policy, each key of `hosts` (`pc`). The ping of `specs/ap/check.md` R4 (`tailscale ping` within 10 seconds), then, when it answered, one `tailscale ssh <ssh>` bound to 30 seconds whose fixed text prints the CPU count, the one-minute load and the `MemAvailable` of `/proc/meminfo` in kB on one line and nothing else: no Windows program, no `ont`, no write. Both calls are the functions of `crates/ap/src/check.rs` that `ap check` calls too, with the environment of check R7. No answer to either, or a line the probe reader of check (`probe_line`) cannot read, is `answers` false, `free` false and no reading. Else `answers` is true, the readings are the probe's (`load_x100` its load times 100, rounded; `available_mb` its reading (a), the Linux `MemAvailable` in MB, the only memory read), and `free` is the rule of check R4 on them: the load below `busy_load` times the CPUs and the memory at least `min_available_mb`.
- R5: The store's hosts. For `local` and each host of the policy, one `ont get` of the `host`; only when it answers that the store has no such host, `declare_host` with the key, `machine` the key and `node` the trimmed text of `/proc/sys/kernel/hostname` for `local`, the host part of `ssh` for a host of the policy (a hostname that cannot be read is the node `local`). A host the store has is never declared by the pass. Then `observe_host` with `answers`, `free`, the readings it has and, when it answers, `seen_at` the pass's time. A host a Lead declared that no policy names (the user's own node of the PC, `machine` `pc`) is never declared or observed by the pass.
- R6: The samples. One line for each host of R5 and pass, all appended by one write to `<dir>/<YYYYMMDD>.samples.jsonl` (the UTC day of the pass): `type` `host_sample`, `key` `<host>@<observed_at>`, `observed_at` (the pass's time in whole seconds), `at` (that time as UTC text `YYYY-MM-DDTHH:MM:SSZ`), `host`, `answers`, `free`, each reading it has (`cpus`, `load_x100`, `available_mb`) and, for `local` when the search of R3 answered, `slots`, `units_running`, `units_ready` and `cpu_waits`. The lines are written whether or not the store answered. No key is written twice: when the last line of the day's file has an `observed_at` at or after the pass's second, the pass waits for a later second, at most 2 seconds, and its time is that second; still none later, it appends nothing and names `samples` in `failed`. A file of the name form `<YYYYMMDD>.samples.jsonl` whose day is more than 14 days before the pass's day is removed; no other file is removed.
- R7: The checks. The log is the file of `specs/ap/check.md` R15 (`AP_CHECKS_LOG` when it is set and not empty, else `/var/lib/agent-platform/checks.jsonl`); it is only read, and no file is no check. A line is kept when it is a JSON object the schema takes: `end` of the form `YYYY-MM-DDTHH:MM:SSZ` at most 30 days before the pass and not after it; `host` `pc` or `local`; `repository`, `head` and `dir` strings; `command` an array of strings; `seconds` a number from 0 whose milliseconds, rounded, fit 64 bits (a signed integer); `exit` an integer; `start` absent, null or of the form of `end`; `reason` absent, null or a string of at most 40 bytes; and its record at most 65,536 bytes. A line equal in bytes to an earlier one is taken once; every other line that is not kept counts in `skipped`. The kept lines, the newest 50,000 by `end` (then by place in the log), are written under a temporary name and renamed to `<dir>/log.checks.jsonl`, one record each: `type` `check`, `key` (the first 32 hexadecimal digits of the SHA-256 of the log line), `observed_at` (`end` in seconds), `command` (the words joined by one space, cut at 1,000 bytes at a character boundary), `milliseconds` (`seconds` times 1000, rounded), and the line's own `host`, `repository`, `head`, `dir`, `end`, `exit` and, when present and not null, `start` and `reason`. A log that exists but cannot be read names `checks` in `failed` and keeps the previous file.
- R8: The accounts. For each distinct last path component of the directories of the policy's `accounts` (a final `/` taken off), `runtime` is the part before `/` of the first key, in byte order, whose list names it. Then one `ont get` of the `account`; one search of `run` by `eq` on `account` and `gt` on `ended_at` (the account's `limit_at`, else 7 days before the pass), every page read whether or not it is qualified (a running run has no `ended_at`); of the runs found whose `limit` reads as `specs/ap/watch.md` R22 reads one (a JSON object with a `windows` object or a `utilization` number), the one with the latest `ended_at`, then the greatest key. `observe_account` is applied, with the `runtime` and, when such a run was found, its `limit`, `ended_at` as `limit_at` and key as `limit_run`, when the store has no such account or such a run was found; else nothing.
- R9: The end. After the files are written, `ont index --source host_samples --source checks` (with `--store` when given). A step that fails does not end the pass: it is named in `failed`, in this form: `units` (R3), `declare_host:<key>` (its `get` or its apply), `observe_host:<key>`, `samples` (R6), `checks` (R7), `observe_account:<key>` (its `get`, its search or its apply), `index` (the call failed or a source did not answer `ok`). The pass prints one JSON line on standard output: `at` (the pass's time as UTC text), `directory`, `hosts` (for each host of R5, the members of its sample but `type`, with `declared`, whether this pass declared it), `accounts` (`[{account, observed}]`), `checks` (`{records, skipped}`), `removed` (the names of R6), `sources` (of each source, the index answer's `status`, `code`, `appended`, `renewed` and `unchanged`, or null when the call failed) and `failed`; it exits 0 when `failed` is empty, else 3. An error of the pass's own (a file of the directory it cannot write, the lock) prints `{"error":{"code","field","detail"}}` on standard error and exits 3.
- R10: The pass's effects are its files in the directory (`resource.lock`, the samples files, `log.checks.jsonl` and its temporary file), the actions `declare_host`, `observe_host` and `observe_account`, `ont index` and its other calls of `ont`, and the calls of `tailscale` of R4. It never writes the checks log, the policy file, a unit's directory or a file outside its directory, and never applies `state_allowance`, which is the Lead's.
- R11: The functions. `ap` with no argument and `ONT_FN_NAME` `capacity` or `gate` in its environment (`specs/ont/fn.md` R8) reads the parameters, one JSON object, from standard input and the store at `ONT_FN_STORE` through read calls of `store.rs` only, and prints one JSON value on standard output, exit 0. Its searches of `run`, `host_sample` and `check` read every page, qualified or not, in pages that keep an answer of `ont` under 1 MiB. A member the function does not declare, or one of another form, is `invalid_input` with the member as the field, exit 2; a named intent the store does not have is `unknown_intent` (field `intent`), exit 2; a store it cannot read exits 3. The error is `{"error":{"code","field","detail"}}` on standard error, as `specs/ap/route.md` R15. A function writes nothing, applies no action and reads no file of the host.
- R12: `capacity` takes no parameter and answers `{"at", "hosts": [{"host","node","machine","answers","stale","observed_at","seen_at","cpus","load_x100","available_mb","free"}], "machines": [{"machine","hosts","up","cpus","load_x100","available_mb","free"}], "accounts": [{"account","runtime","allowance","source","at"}], "can_start": [<machine>]}`, each list by key, a property a head lacks null. `at` is the engine's `now` (the envelope of its first answer). A host is `stale` when its `observed_at` is more than 600 seconds before `at`; a host never observed has `answers` null and `stale` false. A machine is `up` when one of its hosts answers and is not stale; its three readings are those of such a host, the one with the latest `seen_at` (then the least key), counted once however many of its hosts answer, and null when it is not up; it is `free` when it is up and that host is `free`. `can_start` names the free machines. An account's `allowance` is its `limit` read as JSON (the text itself when it is not JSON), `source` `run` and `at` its `limit_at`; without a `limit`, its `allowance` text, `source` `stated` and `at` its `allowance_at`; else the three are null.
- R13: `gate`: the form, and G1 to G3. `since` is a UTC time of the form `YYYY-MM-DDTHH:MM:SSZ`; `intent`, when given, a key of 1 to 512 bytes. The answer is `{"since", "at", "samples", "rows": [{"gate","verdict","text"}]}`, the rows in the order of R13 to R16; a row prints as the verdict left-aligned in six columns, a space and the text (`row_line`). Where no verdict is named, it is `PASS` when the inequality of the text holds for the value before it is rounded for the text, else `FAIL`. The samples are those of `local` whose `at` is at or after `since`; `samples` is their number n. With n under 12 the one row is `G1-G3`, `N.A.`, `G1-G3 need >= 12 samples since <since> (have <n>)`. Else: `G1`, `G1 free memory min <m> MB >= 2500`, m the least `available_mb`; `G2`, `G2 load1 p90 per CPU <x.xx> <= 1.50`, x the value at index floor(0.9 × (n − 1)) of the samples' `load_x100` / (100 × `cpus`) in rising order; `G3`, `G3 samples with a cpu wait <p>% <= 10%`, p the share of the samples with `cpu_waits` above 0, in percent with no decimal; `INFO`, verdict `INFO`, `INFO slots full in <p>% of samples; a slot idle with nothing ready in <q>%`, p the share with `units_running` at least `slots`, q the share with `units_running` below `slots` and `units_ready` 0. G3 and INFO take their shares over the samples that hold the counts (R3); with none, G3 is `N.A.`, `G3 needs a sample with counts`, and INFO is left out.
- R14: `gate`: G4 and G5, from the rows that `ap status --indicators [<intent>]` answers (`specs/ap/status.md` R35 to R40), by calling that code. `a` are the rows whose `merged_at` is at or after `since`, `b` those whose `merged_at` is before it; a set's share is its rows whose `first_verdict` is `accept` over all its rows. With both sets: `G4`, `G4 first-accept share <a.aa> vs <b.bb> before (<na> / <nb> units), drop <= 0.15`, `PASS` when share(b) − share(a) is at most 0.15; else `G4`, `N.A.`, `G4 first-accept share needs merged units after <since>`. With `a`: `G5`, `INFO`, `G5 units merged in the window: <na>; check_failed stops: <k>`, k the stops `check_failed` of the rows of `a`.
- R15: `gate`: G6, from the runs whose `ended_at` is at or after `since` and whose `limit` reads as watch R22 reads one. `bad` counts the runs in which a `status`, the reading's own or a window's, is a string other than `allowed` and `allowed_warning`; u is the highest `utilization`, the reading's own or a window's, 0 without one. `G6`, `G6 account rate limit: refused/limited runs <bad> == 0, utilization <u.uu> <= 0.80`, `PASS` when both hold.
- R16: `gate`: G7, from the checks whose `end` is at or after `since` and whose `exit` is 0. A pair is a `dir` with one `command` checked so on `pc` and on `local`; its ratio is the median `milliseconds` on `pc` over the median on `local` (the median of `specs/ap/status.md` R40). `G7`, `G7 check seconds on the PC / on this host: median ratio <r.rr> over <n> worktrees <= 0.50`, r the median of the pairs' ratios and n the number of pairs; without a pair `G7`, `N.A.`, `G7 needs a worktree checked on both hosts since <since>`.
- R17: The timer. `deploy/ap-resource.service` is `Type=oneshot`, `ExecStart=/usr/local/bin/ap resource`, `TimeoutStartSec=180`, the `Environment=` lines for `HOME` and `PATH` of `deploy/ap-watch.service`, the lines of `specs/ap/deliver.md` R52 with `ProtectSystem=full`, and no `Slice=` (a comment says why); `deploy/ap-resource.timer` has `OnCalendar=*:2/5`, `AccuracySec=10s` and `WantedBy=timers.target`. `ap deliver` installs both (`specs/ap/deliver.md` R48 to R50).

## Interface

`ap resource [--directory <dir>] [--store <path>]`; `ont fn capacity` with `{"parameters": {}}`; `ont fn gate` with `{"parameters": {"since": <UTC time>, "intent"?: <key>}}`. The schema's part (`ontology/work.schema.json`, version 17): the object types `host`, `account`, `host_sample` and `check`, the sources `host_samples` (`/var/lib/agent-platform/resource/*.samples.jsonl`) and `checks` (`/var/lib/agent-platform/resource/*.checks.jsonl`), the actions `declare_host`, `observe_host`, `observe_account` and `state_allowance`, and the functions `capacity` (`timeout_ms` 10000) and `gate` (`timeout_ms` 600000), each `answer_bytes` 65536.

Codes of `ap resource`: `usage`, `invalid_input`, `policy_invalid` (exit 2); `reading_failed`, `io_error` (exit 3). The pass's actions carry the client `ap`, the agent `ap-resource`, the session `resource-<the pass's seconds>` and no role.

## Not included

- No caller gives a run's `host` or `uses`, or an install's `host`: `ap run` and `ap deliver` keep their requests.
- No use of `capacity` by the dispatch pass and no admission of `capacity` or `gate` by a stage's door.
- No change of the policy's `hosts` or of its reader: the user's own node of the PC is a host a Lead declares, and the pass never reaches it.
- No reader of `ap policy check` for the pass, no change of the task's sampler, no faster read of the indicators for `gate`.
- No Windows memory reading, no rotation of the checks log, no object for a check line older than 30 days or a sample older than 14.
- G7 compares the calls as they happened, cold or incremental, and a check the door places here has no line in the log; INFO counts the units in the state `running`; the thresholds are fixed numbers of the code.
- No section of `deploy/README.md`, no install on the host, no data migration: no stored run or install gains a host.
- No USD figure of an allowance: `allowance` is the user's text.
