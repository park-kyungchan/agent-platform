# The writer of a unit's page: `ap unit write`

Purpose: the page of a draft unit is written by a fresh session of the role `writer`, a run of `ap run` the store records like every other stage, given the page as the Lead added it, the pages of its dependencies and the repository at `origin/main`; its one output is an amendment, which `ap` itself bounds by the write set the Lead gave and applies by the code of `ap unit amend`, and the page review follows, so that a Lead no longer writes or starts a page's writer by hand and a writer cannot widen what a unit may change.

## Requirements

- R1: The form is `ap unit write <key> [--store <absolute path>]`, by arguments only; any other argument list is `usage` (field `args`). With `ONT_ROLE` `lead` in the environment the call is refused `role_in_environment` (field `ONT_ROLE`). The key has the form of a new key of `ap unit add` (`specs/ap/unit.md` R6: 1 to 59 bytes of lower-case ASCII letters, digits and `-`, beginning with a letter), else `invalid_input` (field `unit`). `--store` goes to every `ont` call and to the stage as `store`. A refusal is one line `{"error":{"code","field","detail","after","unit"}}` on standard error, exit 2: `after` is null when the call applied no amendment, else `amend`; `unit` is the key (null for `usage`).
- R2: The policy file's member `writer` is an object of `model`, `effort` and `permission_mode` (required) and `compact_window`, `timeout_seconds` (1 to 86,400; default 5,400) and `directory` (default `/var/lib/agent-platform/pages`; it fits the schema's `file_path`: `/` then 1 to 399 printable ASCII bytes, no space), each as `ap run` takes it (`model` at most 40 and `effort` at most 16 bytes of letters, digits and `._-[]`, `permission_mode` one of Claude Code's modes, `compact_window` an integer from 100,000 to 1,000,000); another member or form is `policy_invalid` (field `policy`, the detail beginning with `writer`). No policy file, or one without `writer`: `writer_not_configured` (field `policy`). With `--store`, a policy without `writer.directory` is `invalid_input` (field `policy`). The stage's accounts are the list of the first key present among `claude/writer`, `claude/<model>` and `claude` of `accounts` (`specs/ap/policy.md` R6): the first path is `account`, the rest `next_accounts`; no key: `account_not_mapped` (field `writer`); a list that is not 1 to 5 strings: `policy_invalid`. One public function of `crates/ap/src/unit/page_write.rs`, `writer`, reads the member; the reader `writer` of `ap policy check` (`specs/ap/policy.md` R12) and the dispatch pass (`specs/ap/work.md` R24) call it.
- R3: The unit is read with one `ont get` (`unknown_unit`, field `unit`). Its state is `draft`, else `unit_not_draft` (field `unit`); its `write_set` is not empty, else `write_set_missing` (field `unit`). The write set of this read is the bound of the call (R7).
- R4: `<pages>` (the policy's `writer.directory`) and `<home>` (`<pages>/<key>`) are made with mode 0700 when absent; `<home>` is a directory and no link, else `io_error`. The call takes an advisory lock (`flock`, without waiting) on `<home>/lock` (made with mode 0600 when absent, never through a link); held by another call: `write_active` (field `unit`). With the lock held: every record `<home>/<m>.amend.json.run.json` whose `state` is `running` has its scope stopped and read as ended, only when its name is `ap-run-<36 of 0-9a-f->.scope` (another name, or one not read as ended: `run_still_active`, field `record`, `detail` the name), and its `run` object, when it is still `running` with that record, closed with `killed` and the stage's own request id, as `specs/ap/unit-run.md` R7 does for a stage; then every entry of `<home>/work` and `<home>/scratch` is removed, no link followed. Then the file `<home>/started` is written when absent (mode 0600). `<n>` counts the launches of one unit's writer from 1, over all calls: a call's first launch is one above every number that begins a name `<m>.` in `<home>`.
- R5: For a unit with a repository (the clone by `specs/ap/unit.md` R22, with its codes) the call makes the fetch itself: `git -C <clone> fetch --quiet origin main` within 120 seconds; a failure whose output `drive::racing` reads as a locked ref is tried again after a pause of 2 seconds, five tries at most; another failure, and the fifth, is `fetch_failed` (field `clone`). The text is: the text of `ap unit page <key>` without `--for`; the section `## Pages of the dependencies`, with, for each key of `depends_on` in its order, the line `### <key>: <state>` and that unit's page part as `ap unit page` prints it (`specs/ap/unit.md` R30), or, for a key the store does not have, the line `### <key>` and the line `(not in the store)`, and for a unit without dependencies the line `This unit depends on no unit.`; then the frame `crates/ap/src/unit/frames/writer.md`, compiled in. It is written to `<home>/<n>.prompt.md` (mode 0600); a text over 1,000,000 bytes is `prompt_too_large` (field `unit`).
- R6: The working directory `<home>/work/<n>` (the `<n>` of the call's first launch) is, for a unit with a repository, a throwaway copy of the clone at the commit the text names, made as `ap unit ready` makes its own (`specs/ap/unit.md` R23), else an empty directory of mode 0700; every launch of the call uses it, and it is removed at the call's end, whatever the end. The stage is `ap run`'s code: `role` `writer`, `runtime` `claude`, the members and accounts of R2, `cwd`, `prompt`, `out` `<home>/<n>.amend.json`, `answer_schema` `<home>/amendment.schema.json` (written by the call from one constant: an object of exactly the members of R7, `additionalProperties` false), `limits` `{"scratch": "<home>/scratch/<n>"}`, `unit` the key and `store` the call's. A refusal of `ap run` ends the call with its code and field.
- R7: A launch that ended `ok` left one JSON object in `out`, read once (no such object: `amendment_not_admitted`, field `out`). Before any other check of it: a member other than `objective`, `interface`, `invariants`, `acceptance`, `not_built`, `write_set`, `read_first`, `specs`, `verifier_questions`, `implementer`, `verifier` and `estimate_lines` is `amendment_not_admitted` (field: the member; so `class`, `repository`, `depends_on`, `branch` and `notes` never change); a pattern of `write_set` that is not inside the bound is `write_set_outside` (field `write_set.<i>`, `detail` `{"pattern","bound"}`). Inside means: an exact path of the bound itself; or, for a `<dir>/**` of the bound, an exact path below `<dir>` or a `<e>/**` whose `<e>` is `<dir>` or lies below it; compared as path components, each text read by `write_set_pattern` of `crates/ap/src/review.rs`; a text of neither form, in the amendment or in the bound, is outside.
- R8: The unit is read again: a revision other than the one this call last read (after its own amend it reads the unit once, the amend's answer names no revision) is `unit_changed` (field `unit`), a state other than `draft` is `unit_not_draft`; each ends the call with a refusal. Then the amendment is applied by the code of `ap unit amend` (`object::execute`: the checks of `specs/ap/unit.md` R2 to R19, R37 and R39, and no copy of them) with `request_id` `pw-<16 hexadecimal characters drawn once per call>-<counter>`, `agent` `ap-write`, `session` `p-<key>`, `unit` and the amendment's members.
- R9: After an applied amendment the page is looked at by the code of `ap unit review` (`page_review::execute`), for a unit of every class, with a request id of R8's form, the same `agent` and `session`, `unit` and, from the call's second look on, `resume` with the key of the call's last closed look. The reviewer is the policy's `reviews`. `accept` ends the call. A look refused `fetch_failed` (nothing applied) is repeated after 2 seconds, twice at most; then the call ends `look_refused`.
- R10: Three things go back to the same writer session: a refusal of R7 or of R8's amend (`invalid_input` with its `fields`, `page_too_large`, `plain_writes_protected`, a refusal of the store); a refusal of the look by `specs/ap/unit-review.md` R23 (`write_set_missing`, `acceptance_missing`, `tiers_missing`, `write_set_form`, `plain_writes_protected`, `read_first_missing`, `read_first_range`, `clause_missing`, `clause_unnamed`, `acceptance_not_runnable`, `acceptance_timeout`, `acceptance_passes_on_base`, `invariant_fails_on_base`, nothing applied); and the verdict `repair`. Each is one more launch as R6 with `resume` `{"record": <the record of the launch before>}`, a new `<n>`, and as its prompt one fixed sentence followed by the refusal as one JSON line, or by the path of the look's report. A call makes at most three launches: what would go back after the third ends the call. Another failure of the amend (no refusal of R8's list or of the store) ends the call with a refusal.
- R11: The answer, one JSON object on standard output: `unit`; `end`, one of `accept`, `repair` (the third look said so), `refused` (the third launch's amendment or page was refused), `stage` (a launch did not end `ok`), `look_abandoned` (the look closed `abandoned`) and `look_refused` (a refusal of the look that R10 does not name); `launches`, `[{"n","record","state","run"}]` (`run` the key of the stage's `run` object, or null); `amendments`, the number applied; `reviews`, the keys of the looks in order; `digest`, the page digest of the unit as last read (`specs/ap/unit.md` R34); `refusal`, `{"code","field","detail"}` of the refusal that last went back or ended the call, null when the last that went back was a report or the end is `accept`, `stage` or `look_abandoned`. Exit 0 for `accept`, 3 for every other end.
- R12: The call writes the store only through `amend_unit` (R8), the look's actions, the stage's `run` object (`ap run`'s own start and close) and the close of R4; files of its own only under `<home>` (the look writes under the directory of the reviews, the CLI its account, the door its record); in the clone only what its fetch brings; it never applies `ready_unit`.
- R13: The frame `writer.md` begins `## How you work` and says, in this order: the session is the writer of this unit's page, English only, and changes no file but under a directory it makes with `mktemp -d`; its final message is the amendment object alone, with the members of R7 and what each holds; the write set stays inside the one above, and `class`, `repository` and `depends_on` are the Lead's; the objective is sharpened and never widened, and a rule of it that the source contradicts is named in the first sentence of `interface`; every fact about the source is read now in the working directory, the repository at the commit named above, read-only here; each acceptance check is run and ends as its kind requires, one that writes on a copy under `mktemp -d` (no sandbox starts inside this one); the door, `echo '{"parameters":{"words":"<what you look for>","limit":5}}' | ap fn route`, asked before a repository is scanned; and the sentence on parallel reads of the other frames. It names no file of the stage (`out_named_in_prompt`).

## Interface

`ap unit write <key> [--store <absolute path>]`. The policy file's member `writer`: `{"model", "effort", "permission_mode", "compact_window", "timeout_seconds", "directory"}`, the first three required. The files under `<pages>/<key>`: `lock`, `started`, `amendment.schema.json`, `<n>.prompt.md`, the stage's `<n>.amend.json` with `ap run`'s suffixes, `work/<n>` while a call runs and `scratch/<n>` while a stage runs. The answer: `{"unit", "end", "launches", "amendments", "reviews", "digest", "refusal"}`.

Refusals, exit 2: `usage`, `role_in_environment`, `invalid_input`, `policy_invalid`, `writer_not_configured`, `account_not_mapped`, `unknown_unit`, `unit_not_draft`, `write_set_missing`, `io_error`, `write_active`, `run_still_active`, `repository_not_mapped`, `fetch_failed`, `git_failed`, `prompt_too_large`, `unit_changed`, every refusal of `ap run` (R6) and a failure of the store with its code.

The dispatch pass starts this call for a draft unit of a horizon that has no page (`specs/ap/work.md` R24).

## Not included

- No stored copy of a unit's write set as it was added: the bound is the write set the call read.
- No writer on another runtime than Claude, no writable path beyond the scratch directory, no tier per unit for the writer.
- No automatic `ap unit ready`: making a unit ready stays the Lead's command.
- No recovery of a look that a killed call left `running`: the next call's look of the same digest ends `look_refused` (`duplicate_running_review`), and the Lead ends that review with `ap unit review` `abandon` or `finish` (`specs/ap/unit-review.md` R15).
