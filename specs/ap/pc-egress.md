# The proxy of a look on the PC: the network of a look, admitted as this host's proxy admits

Purpose: a look that unit pc-stage runs on the local PC (an agent stage with the limits of `specs/ap/run-limits.md`, placed on the PC) reaches the model provider, GitHub and the crate registry only through a proxy that admits exactly what this host's proxy admits (`specs/ap/run-limits.md` R18): the form, the method, port 443, no literal address, the role's names and the refused address ranges. The proxy is one program, `crates/ap/src/check/egress.py`, which `ap` sends to the PC and which the stage account runs with its own `python3 -I`: its inner part listens on 127.0.0.1 inside the look's network namespace and passes each connection through a Unix socket to its outer part, which judges the request and connects with the PC's own network. Each request is one line that `ap` takes out of the look's error stream and appends to the egress log with the run's record (R19 there). A self-check form answers ready only when the proxy, in the account where it runs, refuses a name off its list, so that no look is placed on the PC whose proxy does not answer.

## Requirements

- R1: The program is `crates/ap/src/check/egress.py`, Python's standard library only, run as `python3 -I <program> <form> <argument>...` or `python3 -I -c <its text> <form> <argument>...`. The forms are `outside <socket> <nonce> <role> <names> <ranges>`, `inside <socket> <port>` and `check`. `<socket>` is an absolute path whose last component is at most 107 bytes; `<nonce>` is 1 to 64 characters of `0-9a-f-`; `<role>` is one of `implementer`, `fixer`, `reviewer`, `verifier`, `writer`; `<names>` and `<ranges>` are comma-separated lists, each possibly empty (a name of `run-limits.md` R18's form, 1 to 255 printable ASCII bytes without a space; a range an IPv4 or IPv6 network in CIDR form with no host bits set); `<port>` is a whole number from 1 to 65535. Another form or a malformed argument is one line on standard error and exit 2. Under a Python older than 3.10 every form writes one line on standard error and exits 3; so that this check is reached there, the text uses no syntax newer than Python 3.7. A `<socket>` of any length is bound (R2) and reached (R3) by its last component, from its directory as the working directory, since a socket address holds at most 107 bytes of path.
- R2: `outside` binds a Unix stream socket at `<socket>` with mode 0600, under its name only once it listens (a path that exists refuses, exit 2), and serves it: at most 64 connections at once, a further one waits its turn. Each connection carries one request, read and judged as `run-limits.md` R18 says: at most 8,192 bytes within 10 seconds; in R18's order `400 form`, `405 method`, `403 port`, `403 literal`, `403 not_listed` against `<names>` with ASCII case ignored and one final `.` dropped, `502 unresolved`, `403 address` against `<ranges>` with an IPv4-mapped IPv6 address read as its IPv4 address (one address of the name in a range refuses), `502 unreachable` (no connection within 10 seconds to port 443 of any address, or to the port R8's seam names, only while the seam is set). Its answers are R18's: a refusal is `HTTP/1.1 <status> <reason phrase>`, an empty line and the close, with no connection opened; an admitted request is answered `HTTP/1.1 200 Connection established` and an empty line, the bytes the client sent after the empty line are relayed first, then bytes both ways until either side closes. Its way out is the PC's own resolver and network. At SIGTERM or SIGHUP it stops accepting, closes every connection and removes `<socket>`, within 15 seconds, and exits 0.
- R3: `inside` listens on 127.0.0.1 port `<port>`; once it listens it writes the line `ready` on standard output and nothing after. It relays each connection byte for byte, both ways, to a new connection to `<socket>`, and closes a connection whose socket cannot be reached. It ends at SIGTERM.
- R4: For each request `outside` read, admitted or refused, one line on standard error, written by one write: a NUL byte, `ap-egress <nonce> <JSON>` and a line feed, the JSON with exactly the members `at`, `role`, `name`, `port`, `status` and `reason` of `run-limits.md` R19 (no `run`), in that order, written before the answer. No other line of the program begins with a NUL byte, and `outside` writes nothing on standard output.
- R5: `check`, in a new temporary directory under `/tmp`, starts the serving of `outside` within its own process (a forked child, not a new run of a file, since under `-c` there is no file of its text), on a socket there, with role `reviewer`, the name `api.anthropic.com` and no range, sends `CONNECT ap-egress-check.invalid:443 HTTP/1.1` and an empty line, and exits 0 with the one line `ap-egress ready <Python's version>` on standard output only when the answer begins `HTTP/1.1 403` and the child's line of R4 has `reason` `not_listed`; else it exits 1. It resolves no name, opens no connection outside the directory, ends its child and removes the directory. Its name is the only one of R18's the program holds, and the program holds no range: `ap` gives the others as arguments.
- R6: `crates/ap/src/run/egress/pc.rs`, a module of `crates/ap/src/run/egress.rs`, holds `ap`'s side: (a) the program's text, compiled in (`include_str!`); (b) the words of `outside` for a role, a socket and a nonce, its names and ranges built from the constants by which this host's proxy judges (`names` and the list `RANGES`, of which `forbidden` and `forbidden_v4` read), so that no name or range is written twice in Rust or at all in Python (R5's name excepted); (c) a function that takes out of a file each complete line of R4 whose nonce is a given one, leaves every other byte of the file in its order (a line of another nonce, a line whose JSON is not R4's, a line cut short, any other output), and appends each line's JSON, with `run` the path of a record, to the egress log: the file `AP_EGRESS_LOG` names in the port's `environment()` when set and not empty, else `/var/lib/agent-platform/egress.jsonl`, created with mode 0600 and appended to by one write per line as `run-limits.md` R19 says, each line's own `at` kept; its members are exactly R19's seven. A line that cannot be appended stays in the file; the log is appended before the file is rewritten, so a failure leaves a line twice and never none. The items are visible to `crates/ap/src/run.rs` and its modules, where unit pc-stage calls them.
- R7: `python3` on the stage account's login `PATH` is Python 3.10 or later. Nothing is installed for the program, which reads no file but the one of R8 and writes nothing but `<socket>` and the temporary directory of `check`.
- R8: When the variable `AP_EGRESS_RESOLVE` names a JSON file (set and not empty) of names to lists of entries, each `<address>` or `<address>:<port>` (an IPv6 address bracketed when it has a port), `outside` resolves from it in place of the system's resolver (a name the file does not hold, or holds as no list of entries, or a file that cannot be read, has no address), judges each address by `<ranges>` as R2 says, and connects to an entry's port in place of 443 where the entry names one. The request's own port is still judged by R2 (`403 port` for any but 443). Only tests set the variable; without it every connection goes to port 443.

## Interface

The forms and their exits: `outside <socket> <nonce> <role> <names> <ranges>` serves until SIGTERM or SIGHUP and exits 0; `inside <socket> <port>` writes `ready` once and serves until SIGTERM; `check` exits 0 with `ap-egress ready <version>` or 1 with nothing on standard output; a malformed form exits 2, an old Python 3; a `<socket>` that cannot be bound, or an `inside` that cannot listen, exits 2 or 1 with one line on standard error. A line of `outside` on standard error is `\0ap-egress <nonce> {"at":"<UTC, RFC 3339 to the second>","role":"<role>","name":<host as written or null>,"port":<port or null>,"status":<200|400|403|405|502>,"reason":<word or null>}\n`, and the line `ap` appends to the egress log is the same JSON with the member `run` after `at`. `ap`'s side is `crates/ap/src/run/egress/pc.rs`: `PROGRAM`, `outside(role, socket, nonce)` (the words after the program's own) and `take(port, errors, nonce, run)`. The test seam of R8 is the variable `AP_EGRESS_RESOLVE`; no test resolves a name or opens a connection outside the host.

## Not included

- The look's launch, its sandbox, its placement and the call of R6's functions: unit pc-stage. The stage account and its Python: its own unit.
- A member `host` in an egress line: the record the line's `run` names says where the look ran.
- A proxy for the checks' account on the PC, whose checks have no network (`specs/ap/check.md` R8).
- The refresh of the PC's Claude sign-in, whose name is not on R18's lists, and any name beyond them.
- Keeping the look's own standard error apart from `outside`'s: only `outside`'s standard error carries R4's lines, and a look that learns the nonce could forge one where the two streams are merged; keeping them apart is unit pc-stage's.
- A `<socket>` whose last component is longer than 107 bytes, and a half-closed connection kept open: `outside` ends a connection when either side closes.
