# Remote store client over HTTP/1.1: `ap` to `ont serve`

Purpose: allow `ap` on a tailnet peer (such as the user's PC) to talk directly over HTTP/1.1 to `ont serve` on the VPS without a local SQLite store or local `ont` subprocess, recording requests and intents and reading status with the peer's tailnet identity verified by `ont serve`, while refusing VPS-only driver verbs clearly in remote mode.

## Requirements

- R1: Remote mode resolution and HTTP transport apply only to the remote-enabled client verbs (`ap status`, `ap request`, `ap intent`, and the store calls they make) and to the VPS-only driver guard (R12, R13). Host-local admin verbs (`ap watch`, `ap resource`, `ap route`, `ap clause`, `ap api`, `ap measure`, `ap run`, `ap quota`, `ap check`) never resolve remote mode or read the policy file for `store_url`. Both `AP_STORE_URL` lookup (`System::store_url_env`) and the client's policy-file path lookup (`System::client_policy_file`) cross dedicated `System` port methods that default to `None` on test fakes and delegate on `Host` to `std::env::var_os("AP_STORE_URL")` and `self.policy_file()`.
- R2: Precedence of `--store` and `AP_STORE_URL`: an explicit `--store <path>` always selects local `ont` subprocess mode without reading `AP_STORE_URL` or the policy file's `store_url`. Otherwise, when `AP_STORE_URL` is set and non-empty via `System::store_url_env`, it is validated strictly as a `store_url` (`specs/ap/policy.md` R19); an invalid or non-UTF-8 value refuses `store_url_invalid` (`field: "store_url"`, exit 2) before any store call and never falls back to local `ont`.
- R3: Precedence of policy `store_url`: when neither `--store` nor a non-empty `AP_STORE_URL` is given, remote resolution reads the policy file named by `System::client_policy_file` (`AP_POLICY_FILE` when set and non-empty, else `/etc/agent-platform/policy.json` on `Host`). When the port names no path or the file does not exist, local mode is selected. An existing file that is unreadable, too large, not JSON, not one JSON object, or holds an invalid `store_url` refuses `policy_invalid` (`field: "policy"`, `detail` starting with `"file"` or `"store_url"`, exit 2) before any store call. A valid `store_url` selects remote HTTP mode; an absent `store_url` selects local mode. Reading `store_url` for remote mode does not require `models` or `accounts`, so a minimal PC policy `{"store_url":"http://<tailnet-ip>:<port>"}` works.
- R4: Tailnet IP validation (`100.64.0.0/10` for IPv4 or bracketed `[fd7a:115c:a1e0::/48]` for IPv6, port `1..=65535`, no DNS name, userinfo, path, query, fragment, whitespace, or control character) is never bypassed by any CLI flag or environment variable; tests inject TCP transport through `host::WayOut::connect` while exercising the real tailnet URL validator.
- R5: Remote store calls use stdlib `TcpStream` through `host::WayOut::connect` with zero external HTTP crates, enforcing the call's millisecond bound `ms` as the connect timeout, socket read/write timeout, and overall deadline. A connect, timeout, or transport I/O error refuses `store_unreachable` (`field: "store_url"`, fixed non-secret `detail` `"connect"`, `"timeout"`, or `"io"`).
- R6: Every remote call sends `POST <path> HTTP/1.1` with headers `Host`, `Content-Type: application/json`, `Content-Length`, `Connection: close`, `X-Ont-Client` (the value of `--client <val>` in the command arguments, default `ap`), `X-Ont-Role` only when `ONT_ROLE` is set and non-empty in `System::environment()`, and `X-Ont-Agent` only when `ONT_AGENT` is set and non-empty in `System::environment()`, and never sends `Transfer-Encoding`. Any `\r`, `\n`, or byte outside printable ASCII (`< 0x20` or `>= 0x7f`) in `ONT_ROLE`, `ONT_AGENT`, or `--client` (or an empty/missing `--client` value) is refused locally before connecting with `invalid_input` (`field` `"ONT_ROLE"`, `"ONT_AGENT"`, or `"client"`).
- R7: Command-to-endpoint mapping matches `ont serve`: `describe` -> `/v1/describe` (`{}` when body is null), `get` -> `/v1/get`, `search` -> `/v1/search`, `around` -> `/v1/around`, `aggregate` -> `/v1/aggregate`, `log` -> `/v1/log`, `render` -> `/v1/render` (body `{"view","args"}`), `action list` -> `/v1/action/list`, `action validate` -> `/v1/action/validate`, `action apply` -> `/v1/action/apply` (stripping `--client <val>` into `X-Ont-Client` while keeping body `role`), and `fn <name>` -> `/v1/fn` (injecting `"name": <name>` into the JSON request body object without adding unknown fields). Any unserved `ont` command (`index`, `backup`, `schema`, `serve`, `mcp`, or `render` with extra CLI flags) refuses locally before connecting with `operation_not_served` (`field: "command"`, `detail: <subcommand>`).
- R8: Response parsing reads the HTTP/1.1 header block up to `\r\n\r\n`, bounded to at most 16,384 bytes; rejects bare CR or LF in headers, any `Transfer-Encoding` header, malformed or conflicting `Content-Length` headers, and malformed status lines; bounds the response body to `host::ANSWER_LIMIT` (8,388,608 bytes); and requires exact `Content-Length` bytes when `Content-Length` is present, refusing any violation with `store_answer_unreadable`.
- R9: Status mapping: HTTP `200` maps to `Reply { success: true, .. }`; `400`, `403`, `404`, `405`, `413`, `431`, and `503` map to `Reply { success: false, .. }` so `store.rs` parses engine refusal JSON (`store_busy` retries up to 5 times, `unavailable` returns `None` from `get`/`head`/`head_now`, and `peer_not_identified`, `server_busy`, `not_granted` pass through verbatim); any other status code (such as `500`) fails with `store_answer_unreadable`.
- R10: `ap status` (overview, `<key>`, `--brief`, `--text`, `--indicators`, `--term`, `--page`, `--wait`), `ap request` (`record`, `supersede`, `route`, `list`, `--text`, and hook form), and `ap intent` (`show`, `draft`, `amend`, `note`, `lead`, `assume`, `confirm`, `criterion`, `close`, `retire`, `end_delegation`, `--text`) resolve remote configuration once per invocation and operate over HTTP in remote mode without opening any local SQLite store or spawning `ont`.
- R11: In remote mode, `ap status` skips reading local VPS delivery files (`/etc/agent-platform/deliver.json`, `/var/lib/agent-platform/deliver/last.json`) and local systemd/unit files (`watched()` / `work::observe`), reporting `delivery: null` and an empty `idle` set so local PC files are never reported as VPS state. For `ap status --wait`, remote configuration resolution runs before entering the wait loop so `store_url_invalid` and `policy_invalid` fail fast with exit 2 and zero retries rather than retrying inside `reading()` (exit 3).
- R12: The VPS-only driver guard allows `--help`, `-h`, `<verb> --help`, `version`, `--version`, `policy check`, non-driver verbs, and any invocation containing `--store` first, without reading or validating `AP_STORE_URL` or policy `store_url`.
- R13: For `deliver`, `work`, `unit ready`, `unit run`, `unit review`, and `unit write` without `--store` and without `--help` or `-h`, the guard resolves remote mode before touching the store or spawning subprocesses: when remote mode is active with a valid URL, it refuses with exit 2, empty stdout, and one JSON line on stderr `{"error":{"code":"remote_mode_unsupported","field":"verb","detail":"<verb>"}}` (`<verb>` is `"deliver"`, `"work"`, `"unit ready"`, `"unit run"`, `"unit review"`, or `"unit write"`); when `AP_STORE_URL` or policy `store_url` is malformed, it refuses with exit 2 and `store_url_invalid` or `policy_invalid` on stderr instead of falling back to local mode.

## Interface

Configuration sources, in order of precedence for remote-enabled client verbs (`ap status`, `ap request`, `ap intent`):

1. `--store <path>`: local `ont` subprocess mode (`AP_STORE_URL` and policy `store_url` are not read).
2. `AP_STORE_URL` environment variable (when set and non-empty): strict tailnet URL `http://<tailnet-ip>:<port>`.
3. Policy file (`AP_POLICY_FILE` when set and non-empty, else `/etc/agent-platform/policy.json`) top-level optional string member `store_url`.

Refusals added by the remote client (all JSON `{"error":{"code","field","detail"}}` on stderr, exit 2):

- `store_url_invalid` (`field: "store_url"`): invalid or non-UTF-8 `AP_STORE_URL`.
- `policy_invalid` (`field: "policy"`, `detail` starting with `"file"` or `"store_url"`): unreadable, malformed, or invalid-`store_url` policy file.
- `store_unreachable` (`field: "store_url"`, `detail: "connect" | "timeout" | "io"`): TCP connect, deadline timeout, or socket I/O error.
- `operation_not_served` (`field: "command"`, `detail: <subcommand>`): `ont` command not served by `ont serve`.
- `invalid_input` (`field: "ONT_ROLE" | "ONT_AGENT" | "client"`): unsafe header value containing control or non-ASCII bytes.
- `remote_mode_unsupported` (`field: "verb"`, `detail: "<verb>"`): VPS-only driver verb invoked in remote mode.

## Not included

- No TLS termination or HTTPS client (transport encryption and peer identity come from Tailscale WireGuard and `ont serve` LocalAPI whois).
- No `Transfer-Encoding: chunked` request or response streaming and no HTTP keep-alive connection pooling.
- No remote transport for host-local admin verbs (`ap run`, `ap quota`, `ap watch`, `ap check`, `ap route index`, `ap clause index`, `ap resource`, `ap api`, `ap measure`) and no change to `ont` or `ontology/work.schema.json`.
