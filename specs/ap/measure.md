# Measures: `ap measure` and the functions `cost`, `flow` and `share`

Purpose: what the work cost is read from the store, not from scripts of a task directory. Every Claude Code session of this platform's agents and stages on this host is a `run` object with its role, model, tokens, host, account, start and end, its list-price spend by UTC day and its refusals: `ap measure sessions` measures the run `ap run` made for a stage and records a session no `ap run` started (a Lead's, its subagents', a page writer's) from the session records and the stage records, `ont fn cost` answers what a window cost by role, intent, unit or day, per merged unit, the Lead's share and the API credit's spend, `ont fn flow` how an intent's merged units flowed (a day, minutes to merge, stops, page looks) and `ont fn share` how much of the write steps and fact reads went through the store; `ap measure kpis` records each KPI of a confirmed intent once a day from them, and a timer runs both passes each night. The objects, actions and functions are those of schema version 19 (`ontology/README.md`, "Version 19: sessions as runs, KPIs of an intent, measures"); the words of a role, a route and a session's cwd are those of the read-out `evals/readout.py`.

## Requirements

- R1: `ap measure <pass> [<option>...]`, the passes being those a requirement of this file names (here `sessions`); `ap measure --help` prints the usage of every pass (`specs/ap/verbs.md` R2) and exits 0; any other first argument (none included) is refused `usage` (field `args`), exit 2, with `{"error":{"code","field","detail"}}` on standard error.
- R2: `ap measure sessions [--since <YYYY-MM-DD>] [--accounts <dir>]... [--work-root <dir>] [--platforms-root <dir>] [--stage-dir <dir>]... [--prices <file>] [--store <path>]`, each path absolute; `--accounts` and `--stage-dir` may be repeated, every other option is given at most once. Defaults: `--since` two days before the pass's UTC day (the port's wall clock); `--accounts` each directory `$HOME/.claude*` (`HOME` of the port's environment) that holds a directory `projects`, by name; `--work-root` `/home/palantirkc/work`; `--platforms-root` `/home/palantirkc/platforms`; the stage directories `/var/lib/agent-platform/units` and `/var/lib/agent-platform/reviews` (given ones replace them); the prices `evals/prices.tsv` built into `ap`. Another argument list (an unknown option, an option without its value, one given twice, an argument that is not UTF-8) is `usage` (field `args`); a malformed value (a day of another form or not of the calendar, a path that is not absolute, a price file that cannot be read as the read-out's `load_prices` reads it) is `invalid_input` with the option's name without dashes as the field (`since`, `accounts`, `work-root`, `platforms-root`, `stage-dir`, `prices`, `store`); both exit 2 before any effect.
- R3: What is read, and the Academy. Every `*.jsonl` under `<account>/projects` and under `<account>/homes/<name>/projects` of each home `<name>` (the read-out's `projects_dirs`) whose modification time is at or after `--since` (its day at 00:00 UTC) gives messages, its account `<account>`; an older one gives only the start and first cwd of its sessions, as in the read-out. No file under a project directory (a directory directly in a `projects` directory) of either tree whose name contains `-edu-` or `-education-platform` is opened, and no directory whose name begins with `edu-` is opened by any walk: their sessions are not recorded, and each such directory counts once in `files.skipped_academy`. Stage records are read as the read-out's `read_stages` reads them (the work root's `*/**/*.run.json`, a stage directory's `*.run.json` and `*/*.run.json`, a record read from a stage directory marked as such, a file reached both ways read once), with that skip. Codex, Muse Code and Antigravity records are not read.
- R4: Messages, as the read-out's `read_claude`: an assistant line whose `message` holds a string `id` and an object `usage` is one message per id, its token counts the largest seen of each kind, owned by the earliest-started session that holds it (a session's start the earliest `timestamp` of its lines in every file read, an older one too; then by session id), a session's cwd that of its earliest line. A message's cost is the read-out's `cost` with R2's prices (the `+long` rate of a model whose prompt passes its `long_over_tokens`; 0 for a model without a price), in millionths of a USD rounded to the nearest; its day is the first ten characters of its earliest `timestamp`. A pass counts only messages whose day is at or after `--since`; each file that holds such a message was modified on or after that day and is read, so the owner rule sees every session that holds it and a fork never takes a message its first session owns.
- R5: The run of a message, and what is recorded. With stage records of its owner session: the latest of them that started at or before the message, else the first (the read-out's bisect on `start`), and its role; its route is `engineering` when that record was read from a stage directory, else the read-out's `route_of` of the session's cwd with that record. Without: the role of the read-out's `role_without_stage` with no `--lead-cwd` (`lead`, `worker, no record` or `interactive`) and `route_of` of the cwd; the lesson directory is `<work root>/edu-lessons`. A run is one stage record of a session, or a session without one; only a run of route `engineering` is recorded or measured: a run of route `temporary`, `other` or `lesson` (the eval suites' sessions among them) counts in `skipped_route` and nothing else. The intent of a run the pass makes: the intent whose `directory` is the session's cwd or its longest parent, else the intent whose `lead_session` is the session, else none (the intents read with `store::search_every`).
- R6: The objects. One `store::search` of `run` per pass, filtered only on the required `runtime` (`eq` `claude`, the word `crates/ap/src/run.rs` gives a Claude stage, also the pass's), every page read (a filter on an optional property would leave pages unqualified, engine `specs/ont/read.md` R74), with no bound of time, so that a long session's run is always found; `session` and `record` are matched in the pass: a run whose `record` is the path of a stage record the pass read is that record's run; a run of `state` `session` without such a `record` is that of its session. A run not found is made by `record_session` (request id `measure-<first 32 hex of the SHA-256 of "<runtime>:<session>:<record path or empty>">`) with `session`, `role`, `runtime` `claude`, `model` (that of most of its messages, then the smallest name), `started_at` and `ended_at` (its first and last message, to the second), `account` and `uses` (the account directory's last component), `host` `local`, `intent`, `record` (when it is a `file_path` of the schema) and the four token counts (`cache_write_tokens` the 5-minute and 1-hour writes). A run of `state` `session` found with messages later than its `ended_at` gets `extend_session`: `ended_at` the latest, and the stored token counts plus those of the later messages. `measure_run` goes to a run made in the pass, to a run found that holds a message (R4) or a door line (R7) of a day at or after `--since`, and to one found without `measured_at`, started on or after that day, whose stage record the pass read; any other run is left as it is (`unchanged`), so older runs and runs whose files are gone keep their `days`. It carries `days` (its stored entries of days before `--since`'s day kept, those from that day on replaced by the pass's, by day) and `refusals` (the sum of its `days`' refusals), under the request id `measure-<those 32 hex>-<first 16 hex of the SHA-256 of its parameters as canonical JSON>` (`extend_session` likewise with `-x-` before the 16 hex), so a pass that finds nothing new applies nothing new. Every apply goes through `store::unit_action` as the agent `ap-measure`; an apply that gave no answer is not repeated in the pass.
- R7: The counts of a day. Each entry of `days` counts only what is dated that day, so a pass that recomputes and replaces the days it reads (R6) is idempotent. Reads and writes: a call is a `tool_use` block of an assistant line, a `<synthetic>` line's too (the calls of a code-mode script), counted once by its id over all files read, for the session that owns its message (R4), on the run of its line's time (R5) and on its line's day; `REPL` and `Poll` are not counted. `Read`, `Grep`, `Glob`: a file read; `Write`, `Edit`, `MultiEdit`, `NotebookEdit`: a file write; the tools of the engine's MCP server (`mcp__ont__<tool>` in this host's sessions): `ont_action_apply` a store write; `ont_describe`, `ont_get`, `ont_search`, `ont_log`, `ont_fn`, `ont_action_list` and `ont_action_validate` a store read; `ont_index` and any other tool nowhere. A `Bash` command is split at `&&`, `||`, `;`, `|` and line breaks; each part, after leading `cd set export time` and assignments (and a program's path before its name, `git`'s options `-C <dir>` and `-c <value>`, and `ont`'s `--store`, `--now` and `--client` with their values), counts once by its first words: a store write `ap` with `request intent deliver run api resource measure` or `unit add|amend|ready|drop|review|approve|reject|run|write`, and `ont action`; a store read `ap status`, `ont search|get|aggregate|describe|log|around|fn`; a file write `git add|commit|mv|rm`, `sed -i` and each of `tee mv cp rm mkdir install chmod touch`, and one more for a part that is not `ap` or `ont` and redirects (`>` or `>>`) to a path other than `/dev/null` (a target `&<n>` is no path); a file read each of `cat sed grep rg head tail wc ls find awk jq diff sha256sum stat du` and `git show|log|diff|grep|ls-tree|status|rev-parse|cat-file|ls-files|blame`; anything else counts nowhere. The door's record (`specs/ap/door.md` R6: `AP_DOOR_LOG` of the port's environment or its default; a missing file is no line) is only read: each line whose `verb` is `fn` and `exit` 0 adds one store read to the run whose `record` is the line's `run`, on the day of its `at`. Refusals: in the `tool_result` blocks of user lines: each object `{"error":{...}}` whose `code` is a string (a refusal of `ap`) and each `"code":"<c>"` followed in its object by `"status":"refused"` (a refusal of `ont`), in the block's text as it is or with its escaped quotes read as quotes, whichever shows more. A block counts once by its `tool_use_id` over all files read (a fork's copy holds the same id), as a call does: R4's owner of its `tool_use`, R5's run and its line's day. Within one run, a refusal shown both in a call's result and in its carrier's (`REPL`, `Poll`) counts once: per second, code and field, the larger of the two counts.
- R8: The end and the bounds. The pass's effects are `record_session`, `extend_session` and `measure_run`; it writes no file; of an account directory it lists `homes` and reads only `projects/**/*.jsonl` and `homes/*/projects/**/*.jsonl`. A failed apply does not end it. It prints one JSON line: `at` (the pass's time, UTC to the second), `since`, `files` (`read`, `skipped_academy`, `unreadable_lines`), `skipped_route` (the runs of R5 not of route `engineering`), `runs` (`recorded`, `extended`, `measured`, `unchanged`: the runs found and not applied to), `failed` (counts by action); exit 0 when `failed` is empty, else 3; an error of its own (a search of the store that fails) `{"error":{"code","field","detail"}}` on standard error, exit 3. No output, answer or store value of this file holds a message's text, a tool's input, a cwd or a path, but a run's `record`.
- R9: The functions, the common part: `ap` with no argument and `ONT_FN_NAME` `cost`, `flow` or `share`, as `specs/ap/route.md` R15. The parameters, one JSON object, on standard input; the store at `ONT_FN_STORE`, through read calls of `crates/ap/src/store.rs` only; one JSON value, exit 0. `since` and `until` are UTC days `YYYY-MM-DD`, `since` not after `until`, at most 92 days; `by` is `role`, `intent`, `unit` or `day` (default `role`); a member not declared, or of another form, is `invalid_input` with the member as the field, an intent the store does not have `unknown_intent` (field `intent`), exit 2; an unreadable store exit 3; the error object of `specs/ap/route.md` R15. A function writes nothing, applies no action and reads no file of the host (`merged` by `status::execute`, as `gate` calls it, reads only the store); it reads `run` and `unit` with `store::search_every` (every page, qualified or not) and filters in the process. A run "counts in the window" when an entry of its `days` is in it; with `intent`, only a run whose `intent` is it or whose `unit`'s `intent` is it.
- R10: `cost`: `{since, until, by, intent, groups: [{key, usd, messages, runs}], total_usd, merged, usd_a_pr, usd_stages_a_pr, usd_lead_a_pr, lead_share, lead_refusals_a_pr, api: {settled_usd, reserved_usd}, unmeasured}`, `groups` by key; a run without a unit (every session run) or without an intent is grouped under `key` null, listed last; with `by` `day` a run counts in the group of each of its days in the window. Only the `days` entries in the window count, summed in micro-dollars and rounded to 0.01 USD once. `merged`: the rows of `ap status --indicators [<intent>]` (`specs/ap/status.md` R35) whose `merged_at` day is in the window. Over `merged`: `usd_a_pr` the total; `usd_stages_a_pr` the roles `implementer`, `fixer`, `verifier`, `reviewer`; `usd_lead_a_pr` the roles `lead` and `writer`; `lead_refusals_a_pr` the `refusals` of the `days` entries in the window of the runs of role `lead`; each rounded to 0.01 and null when `merged` is 0. `lead_share`: `lead` and `writer` over the total, in percent to one decimal, null at 0. `api`: `specs/ap/api.md` R9's spend of the window (the runs of role `batch` that started in it), split into `settled_usd` and `reserved_usd`, in USD rounded to 0.01. `unmeasured`: runs started in the window without `measured_at`.
- R11: `flow`: `{intent, since, until, merged, merged_a_day, median_minutes, packet_first_accept, units_stopped, stops, page_looks, looks_after_accept, first_accept, log_cut}`, the parameters `intent`, `since` and `until`, each required and no other member (R9's rules; an intent the store does not have is `unknown_intent`). The merged units are the rows of `ap status --indicators <intent>` (`specs/ap/status.md` R35, by calling that code) whose `merged_at` day is in the window, `merged` their number and `merged_a_day` that number over the window's days, to two decimals. `median_minutes` is `specs/ap/status.md` R40's median of `minutes` over those rows, and `packet_first_accept` R40's `first_accept_share` over them. `stops` is each `cause` of their `stops` counted, `{<cause>: n}`, and `units_stopped` the rows with a stop. A unit's page looks are its reviews of kind `page` and status `closed` (a `revoked` or `running` review is none), ordered by `closed_at`, then key: `page_looks` is their number over `merged`; `looks_after_accept` the looks of a unit that closed after its first look whose verdict is `accept`, over `merged`; `first_accept` the share of the merged units whose first look is an `accept`, to three places (a unit without a look is not one). `page_looks`, `looks_after_accept` and `first_accept` are rounded to 0.01, 0.01 and 0.001, and each is null with no merged unit; `log_cut` is true when a row has it.
- R12: `share`: the parameters `since`, `until` and `intent` (optional), no other member. Of the runs that count in the window (R9), by role: `{role, runs, file_reads, store_reads, file_writes, store_writes, read_share, write_share}`, a share being the store's count over the store's plus the file's, in percent to one decimal (null at 0): `read_share` of the reads, `write_share` of the writes. The same, with `group` for `role`, for the groups `stages` (the roles `implementer`, `fixer`, `verifier`, `reviewer` and `writer`) and `sessions` (every other role but `batch`, which no group counts). The answer is `{since, until, intent, roles: [...], groups: [...]}`, `roles` by role, `groups` `stages` then `sessions`. The groups differ from `cost`'s on purpose: a `writer` is a stage of `ap run` that reaches the store only through the door, so `share` counts it with the stages, while `cost` counts its spend with the Lead's (`usd_lead_a_pr`, `lead_share`), as the KPIs `usd_lead` and `lead_share` define it.
- R13: The counts of `share`: for each run that counts in the window, the sum of the four counts (`file_reads`, `store_reads`, `file_writes`, `store_writes`) of those `days` entries whose `day` is in the window (R7), so a run across the window's edge counts only its days inside it; an entry without a count counts 0. `share` keeps no count of its own, applies no action and changes nothing of the pass `sessions`: the counts are what that pass stored, the calls of code-mode scripts and the door's record included.
- R14: `ap measure kpis [--day <YYYY-MM-DD>] [--store <path>]`, a pass of R1, each option at most once (another argument list is `usage`, field `args`), `--store` an absolute path. `day` defaults to the pass's UTC day (the port's wall clock); a day of another form or not of the calendar, or one after the pass's UTC day, is `invalid_input` (field `day`), both exit 2 before any effect. The window is the seven days before `day`, `day` itself not in it. The pass measures the KPIs of the table below ("The KPIs"): each name there with the function it asks and the member of the answer it takes (`flow`'s `stops` takes `units_stopped`, `merged` and `stops`). Each function is asked, as `ont fn` asks it, with the KPI's intent and the window.
- R15: The KPIs of the pass. One search of `kpi` (every page); a KPI is measured when it has an `intent` whose `status` is `confirmed` and a `name` of the table; any other counts in `skipped`. Each is given one `record_measurement` as the agent `ap-measure`, with `observed_at` the pass's time to the second, `evidence` `ont fn <function> <parameters as compact JSON>`, the request id `measure-<the KPI's key>-<day without dashes>`, and `value` a text, a number being as the function answers it and `n/a` standing for null, `<window>` being `<since>..<until>`: for a KPI of `cost` or `flow` but `stops`, `<number> (<window>, <merged> merged)`, `merged` that function's own; for `stops`, `<units_stopped> of <merged> stopped: <cause> <n>, ... (<window>)`, the causes in byte order and `none` for no stop; for `store_writes` and `store_queries`, `sessions <x> % stages <y> % (<window>)`, from the groups' `write_share` or `read_share`, with no `merged`. A `stops` text over 200 bytes (the schema's `max_bytes` of `value`) keeps the causes that fit whole and ends the list with `...`; any other value over 200 bytes, or an evidence over 300 bytes, is a failed measurement (`value_too_long`, `evidence_too_long`) and is not sent. The engine answers a request id it holds with other parameters `request_id_reused`: under this request id that refusal means the KPI was measured that day, so it counts in `unchanged`, not in `failed`, and so does an apply that answers `already_applied`; a KPI therefore has at most one measurement a day, and a second pass of a day adds none. Each function runs once per intent and pass, in the process. A failed measurement (an apply refused otherwise, a function that failed, a text too long) does not end the pass, and its only effect is `record_measurement`. The pass prints one JSON line `{at, day, since, until, measured: [{kpi, name, value}], unchanged, skipped, failed: [{kpi, name, code}]}`, `unchanged` and `skipped` being numbers, and exits 0 when `failed` is empty, else 3; a search of the store that fails is `{"error":{"code","field","detail"}}` on standard error, exit 3.
- R16: The timer. `deploy/ap-measure.service` is `Type=oneshot` and runs `ap measure sessions` and then `ap measure kpis` (the first with the `-` prefix, so that a failed sessions pass does not keep the KPI pass of that night from running), with `TimeoutStartSec=3600`, `Slice=agents.slice`, `Nice=10`, the `Environment=` lines for `HOME` and `PATH` of `deploy/ap-route.service` and the lines of `specs/ap/deliver.md` R52 with `ProtectSystem=full`; `deploy/ap-measure.timer` fires at 00:20 UTC every day (`OnCalendar=*-*-* 00:20:00 UTC`, `Persistent=true`, `WantedBy=timers.target`). Delivery installs both (`specs/ap/deliver.md` R48 to R50). The pass measures the seven days before the day it runs on, so a timer that missed a night leaves that night's measurement unmade, and none is made later.

## Interface

`ap measure sessions [--since <YYYY-MM-DD>] [--accounts <dir>]... [--work-root <dir>] [--platforms-root <dir>] [--stage-dir <dir>]... [--prices <file>] [--store <path>]` and `ap measure kpis [--day <YYYY-MM-DD>] [--store <path>]`; `ont fn cost` with `{"parameters": {"since", "until", "by"?, "intent"?}}`, `ont fn flow` with `{"parameters": {"intent", "since", "until"}}` and `ont fn share` with `{"parameters": {"since", "until", "intent"?}}`. The schema's part (`ontology/work.schema.json`, version 19): the run's `days`, `refusals` and `measured_at`, the actions `record_session`, `extend_session`, `measure_run`, `set_kpi_intent` and `record_measurement`, the KPI's `intent` and the three functions (`program` `/usr/local/bin/ap`, `answer_bytes` 65536, `timeout_ms` 600000). Before the first timer pass the Lead sets each KPI the table names to its intent with `set_kpi_intent`; a KPI without one is skipped.

Codes of `ap measure`: `usage`, `invalid_input` (exit 2); a failed search of the store with the store's code, and a failed apply counted in `failed` (exit 3). Codes of `cost`, `flow` and `share`: `invalid_input`, `unknown_intent` (exit 2), the store's codes (exit 3). Codes of a failed measurement of `kpis`: `value_too_long`, `evidence_too_long`, the store's codes.

The timer's undo: `systemctl disable --now ap-measure.timer`; the runs and the measurements stay. A pass run by hand is undone by nothing, and needs none: a later pass of `sessions` replaces the days it reads, a run it made stays a closed run of `state` `session`, and a measurement stays as the immutable history it is.

## Not included

- The timer does not record the KPIs `gate`, `api_spend`, `examination`, `findings_planned` or `real_run`: the Lead does. `share` reads no action log (the log counts actions, not a session's steps), and a window over days before the first pass of `sessions` has no counts for them. No backfill of measurements for days before the first pass, no retention of measurements.
- No Codex, Muse Code or Antigravity usage, no session of the PC, of the Academy, or of route `temporary` or `other` (the eval suites' sessions): only this platform's agents and stages are runs, so the store does not grow by the suites' few hundred sessions a day.
- No change of `ap run`, of `ap status --indicators` (`cost` calls it), of the read-out's figures, or of the files of `deploy/` that exist.
- A page reviewer's spend counts with the role `reviewer`; no review kind is stored on a run.
- `merged` counts units the store merged, not other pull requests; no `gh` call.
- No retention of runs; no backfill beyond `--since`; no faster read than one search of every Claude Code run a pass.
