# The always-loaded file: `content/AGENTS.md`

Purpose: every agent of every CLI on this host loads `content/AGENTS.md`, installed as `/root/.agents/AGENTS.md`, at every start through its CLI's pointer file. The file holds what cannot change by task and what agents keep getting wrong, with the order of work of the life cycle, on one page; everything else is read where a task needs it: a skill, the unit's page, a repository's `AGENTS.md` and map, the store (`ap status`, `ap status --term <word>`), the source at `origin/main`.

## Requirements

- R1: The file is at most 6,500 bytes (`AGENTS_BYTE_LIMIT` of `ci/check-content.py`, `file_over_limit`).
- R2: The file has exactly eight sections, with the headings `## 1. Who decides`, `## 2. The order of work`, `## 3. Four commands`, `## 4. Evidence`, `## 5. Effects`, `## 6. The user's standing limits`, `## 7. Language` and `## 8. Where things are`, in this order, and no other `## ` heading (`agents_section_missing`, `agents_section_unexpected`, `agents_sections_out_of_order`). A file of `content/` routes to one of them as "`AGENTS.md` section <n>" (`route_to_missing_section` holds that the numbered heading exists).
- R3: What each section holds, held by the verifier's reading:
  1. Who decides: the user's words bind; the agent the user speaks to completes them, says what it took them to mean and proceeds on work that can be undone; a worker does its page and nothing more.
  2. The order of work: Request, Intent, Spec, Plan, Unit, Deliver, Operate, Retire, one line each; the lanes; and the rule that teaches the order, in its three sentences: "When a request asks for the output of a later stage while the record of an earlier stage is missing, name the missing stage in one line, ask that stage's questions with defaults, and say what you will do without an answer. One message, at most five questions. Not for a question, a stop, an incident, or work that is already in order."
  3. Four commands: `ap status --brief`, run in the task's directory, before anything else, for what is next, stopped, waiting on the user, owed or held; `ap request` for every message of the user, as `specs/ap/request.md` says; `ap unit page <key>` when given a unit; `ap status --term <word>` for what one word means.
  4. Evidence: a fact from source, Git, a compiler, the store or a service's output, read now; a time from the clock; verification by output, not by a success message; merged, installed, loaded and used (the unit's named run happened) as four facts, each shown by its own output.
  5. Effects: no credential printed, nor written into a file, a commit, a store or a message; no session, pane or tree touched that is not the agent's own; a CLI's private memory holds nothing another agent or a later session needs; before deleting, the copy and every consumer verified; a failure reported as `code@path:line` with one cause, and the same failing step not retried unchanged.
  6. The user's standing limits: the Academy's paths; private data as metadata and hashes unless the user authorizes more, and the Academy's records as real data held inside the Academy's own task and never in Git; the allowed models by pointer to the policy file; long-term memory off until the user deploys it anew, with a fact that has a key, a state or an owner kept as an object of the store.
  7. Language: everything except a message to the user in English; a message to the user by the skill `report`.
  8. Where things are: six lines, each an absolute path or a pattern, or the store's commands.
- R4: The file is prose and lists: no line over 400 characters (`agents_line_too_long`) and no line beginning with `|` (`agents_table`), so it holds no table, among them no table of files to read and no table of where to write what is learned.
- R5: Every absolute path the file names exists on the host or is written as a pattern, with `<name>` or `*` (`agents_path_missing`). The check runs where the host is present (`/root/.agents/AGENTS.md` exists, or the file the variable `CONTENT_CHECK_HOST` names, which the tests set) and elsewhere prints one line and skips, as the check of the corpus routes does.
- R6: The file holds no value that changes by task: no model name (`model_name_in_content`), date, version, token window, effort, session or pane id or Git revision (`changing_value_in_always_loaded_text`); such a value belongs to a task's record or the policy file. A count that changes by task is held by the verifier's reading.
- R7: The file holds no glossary: what a word of the life cycle means is the description of its type, action, property or value in the store's schema, printed by `ap status --term <word>`; a word with no entry there is defined in the one file that needs it. Held by the verifier's reading.
- R8: A rule that leaves the file is, in the same pull request, either in another installed file (named in the description with that file and line) or listed as dropped with a reason a reviewer can check; a rule the user set (the standing limits, the language, the Academy, private data, credentials, long-term memory off until the user deploys it anew) is never dropped. Held by the verifier's reading. No file under `content/` names the legacy memory service, Hindsight: `ci/check-content.py` refuses the word, compared without case, in any file under `content/` with `retired_memory_named` and the file and line.
- R9: The gate: a pull request that changes the file merges only when the routing suite, the intake suite and the Lead suite (`evals/README.md`) each run on its head and none is under its recorded baseline; "under" is the routing suite's `run gate` rule. After delivery, one session of each CLI that loads the file (Claude Code, Muse, Antigravity) shows the new text in its own record. For a CLI whose use the user has suspended, the readback is owed: a finding names it until that CLI's first session shows the text. Held by the gate, which the Lead runs; `./check` does not run the suites.

## Interface

`content/AGENTS.md` in the form of R2 to R7. `ci/check-content.py` holds R1, R2, R4, R5, R6 and R8 (the name of the legacy memory service), each with a test in `ci/test_check_content.py` that plants the fault; `CONTENT_CHECK_HOST` names the file whose presence means "this is the host" (default `/root/.agents/AGENTS.md`).

## Not included

- The references under `content/runtime-references/` and the skills that route to them stay until they are removed by their own unit; the file names their directory, not each file.
- No check that a section holds its content (R3) or that a moved rule has its home (R8, but for the name of the legacy memory service): the verifier reads the diff.
- No check that the file mentions nothing removed: it follows the removal of the references.
