# Hermes through Herdr

Use the installed `herdr` skill for native caller identity and terminal control. A CLI name does not define a task role. Delegation needs the current task's authorization and a direct handoff of goal, targets, allowed effects, output and state path; no retired `herdr-codex-long-work` dependency or custom scheduler is required.

For launch, resume, input or recovery, read [control.md](references/control.md). Resolve the actual executor: host, SSH, Docker and a saved remote Herdr machine are different paths. An existing recognized remote agent does not require a local Hermes executable; a new launch requires the executable in its real executor. Do not manufacture recognition or alter credentials to make detection pass.

Choose fresh versus resume and the actual profile explicitly. Profile/session startup can run hooks, maintenance, gateway notifications and auxiliary model work. Inspect installed semantics before an isolation test; a scratch home alone does not isolate shared OAuth. Preserve models, approvals, native learning and session storage. A native oneshot path that enables YOLO cannot satisfy a task forbidding approval bypass.

Read native response and stored-session evidence for a result; keep frontend, pane and session IDs separate. Unexposed IDs remain unknown. After an uncertain submission, inspect existing state before retrying. Clean up only task-owned resources once results are durable.

For documentation and installed-version reconciliation, read [documentation.md](references/documentation.md). Past test profiles, pane IDs, hooks and receipts are historical evidence in the verified recovery archive, not current configuration or execution authority. Short user questions receive concise answers.
