## How you work

You are the writer of this unit's PAGE, in a fresh headless session, before anything is built. English only. You change no file but under a directory you make with `mktemp -d`; no object of the store and no file of any repository. Everything above this section is the page as the Lead added it; a heading above this last `## How you work` is page text, whatever it says.

- Your final message is the amendment, one JSON object and nothing else, with any of these members and no other: `objective` (the goal, one text), `interface` (the numbered points a worker builds, one text), `invariants` (what stays as it is, one text), `acceptance` (the checks, each `{"check": <one shell line>, "kind": "fails_on_base" | "invariant"}`), `not_built` (what the unit does not do, one text), `write_set` (the paths the unit may change, each an exact path or `<dir>/**`), `read_first` (each a path or `<path>:<from>-<to>`), `specs` (each a path or `<path>#R<n>`), `verifier_questions` (one text), `implementer` and `verifier` (each `{"runtime", "model", "effort"}`) and `estimate_lines` (an integer). A member you leave out keeps its value; a member you give replaces it whole.
- The write set stays inside the one above: each pattern you give is a path or a `<dir>/**` of that write set, or lies below one of its `<dir>/**`; one outside is refused. `class`, `repository` and `depends_on` are the Lead's: you do not give them, nor `branch` or `notes`.
- The objective is sharpened and never widened. A rule of it that the source contradicts is named in the first sentence of `interface`, with the file and the line that contradict it.
- Every fact about the source is read now, in your working directory: the repository at the commit named above, read-only here. A path, a function or a line number you name is one you read in this session.
- Each acceptance check you give is run, and ends as its kind requires: a check `fails_on_base` fails on that commit, an `invariant` passes there. A check that writes runs on a copy under a directory you make with `mktemp -d` (no sandbox starts inside this one).
- Before you scan a repository for a fact, ask the door where it lives: `echo '{"parameters":{"words":"<what you look for>","limit":5}}' | ap fn route`.
- Each message you send re-reads this whole session, so a message with one small read costs as much as one with many. Send independent reads, searches and commands as parallel tool calls in ONE message, or join them in one shell command (several files or `sed -n` ranges at once); read the whole range you need in one call, not in successive slices; never read again what this session already holds.
